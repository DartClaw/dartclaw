## 1. HumanLayer SDK / API (human-in-the-loop) 

### Status
- Superseded. SDK code deleted from `humanlayer/humanlayer` in `fd193391` (2025-09-29); docs at `humanlayer.md` say "being superseded by CodeLayer" and "sdks were removed in #646".
- Last releases: PyPI `humanlayer` 0.7.9 uploaded 2025-06-03; npm `@humanlayer/sdk` latest 0.7.9 (npm metadata modified 2026-01-05; no deprecation message returned by `npm view`).
- The cloud API base `https://api.humanlayer.dev/humanlayer/v1` and the old dashboard `app.humanlayer.dev` did not respond from this machine (fetch tool connection error; `host api.humanlayer.dev` returned no records). Not conclusive that the service is shut down; see Open questions.
- New-product docs (docs.humanlayer.com) contain no mention of `require_approval`, `human_as_tool`, or contact channels.
- Sources: https://github.com/humanlayer/humanlayer (commit `746df017` = last tree with SDK; docs read via `git show fd193391^:docs/core/...`), https://pypi.org/pypi/humanlayer/json, https://www.ycombinator.com/companies/humanlayer.

### Mechanism (from the last SDK tree, `746df017`)
Core API objects (Pydantic models, `humanlayer/core/models.py`):
- `FunctionCall {run_id, call_id, spec: FunctionCallSpec{fn, kwargs, channel?, reject_options?, state?}, status?: FunctionCallStatus{requested_at, responded_at, approved: bool|None, comment, reject_option_name, slack_message_ts}}`. This is an approval request for one tool invocation.
- `HumanContact {run_id, call_id, spec: HumanContactSpec{msg, subject?, channel?, response_options?, state?}, status?: {requested_at, responded_at, response, response_option_name}}`. This is a free-form ask.
- `ContactChannel` is a union: `slack {channel_or_user_id, context_about_channel_or_user, bot_token?, allowed_responder_ids?, thread_ts?, experimental_slack_blocks?}`, `email {address, additional_recipients[to|cc|bcc], subject, in_reply_to_message_id, references_message_id, template (Jinja2)}`, `sms {phone_number}`, `whatsapp {phone_number}`. The `context_about_*` string is injected into the LLM tool name/description (e.g. tool becomes `contact_human_via_email_to_the_user_you_are_assisting`).
- `ResponseOption {name, title, description, prompt_fill, interactive}`: structured choices; `prompt_fill` pre-populates the reply text (e.g. "try again but this time ...").
- `Escalation {escalation_msg, additional_recipients?, channel?}`: re-send a pending call by email to more recipients or a different address.
- IDs: `run_id` groups one agent execution (default auto-generated from agent name); `call_id` is per request and may be caller-supplied (e.g. an OpenAI `tool_call_id`) so responses map back to tool calls.
- `state` dict on both spec types is stored server-side and echoed back in webhooks so the caller can be stateless (docs warn to version the state schema).

Entry points:
- `@hl.require_approval(contact_channel=..., reject_options=...)` decorator wraps any function. On call: create `FunctionCall` (POST `/function_calls`), then poll `GET /function_calls/{call_id}` every 3 s (`self.sleep(3)` in `fetch_approval`) until `status.approved` is not None. Approved: run the function. Rejected: return a string `"User denied <fn> with message: <comment>"` as the tool result (the wrapper deliberately changes the return type to `R | str` so frameworks that swallow exceptions still show the LLM the denial).
- `hl.human_as_tool(contact_channel=..., response_options=...)` returns a plain Python function (name/docstring/type hints) usable as an LLM tool; same create + poll cycle on `POST /contact_requests` and `GET /contact_requests/{call_id}` (`CloudHumanContactStore`; responder side `POST /agent/human_contacts/{id}/respond`, approvals `POST /agent/function_calls/{id}/respond`), returns the human's reply text to the LLM.
- Imperative variants: `fetch_approval(spec)`, `fetch_human_response(spec)` (blocking), and `create_function_call` / `get_function_call` / `create_human_contact` / `get_human_contact` (caller owns the wait loop).
- Backend selection: if `HUMANLAYER_API_KEY` is set, `ApprovalMethod.BACKEND` (cloud); otherwise `ApprovalMethod.CLI` which prints the call and uses `input()` ("Hit ENTER to proceed, or provide feedback to the agent to deny").
- Channel config levels: per operation, per `HumanLayer(...)` instance, or project default in the dashboard.
- Composite channels (docs say "in development"): `ContactChannel(all_of=[...])`, `any_of=[...]`, and `{"timeout": 3600, "channel": ...}` for fallback approvers; nested AND/OR.
- Classifications (private beta): `human_as_tool` with `ResponseOption`s for labeling; sync (default) vs async (`createRequest` / `getResponse(callId)`).
- Webhooks (beta, by invitation): response webhooks fire when an approval/contact is requested or completed (payload is the `FunctionCall`/`HumanContact` including `state`); agent webhooks (`v1beta2.agent_email.received`) start an agent from an inbound email (payload: from/to/subject/body/message_id/previous_thread/raw_email). Slack inbound used the same dashboard console. Example agent: https://github.com/dexhorthy/mailcrew.
- Async vs sync: sync = blocking poll loop; async = create now, fetch later or receive webhook; websocket/asyncio client noted as work-in-progress at v0.6.1.
- Slack: HumanLayer-hosted Slack app, or own app with manifest whose event/interactivity URLs point at `api.humanlayer.dev/humanlayer/v1/slack/{events,interactions}`; `allowed_responder_ids` restricts who may answer; blocks UI optional (`experimental_slack_blocks`).
- Other: React embed channel, CLI `humanlayer contact_human -m ...` (reads `HUMANLAYER_SLACK_CHANNEL` / `HUMANLAYER_EMAIL_ADDRESS` / `.hlyr.json`; defaults to web UI when none set), framework docs for LangChain, CrewAI, ControlFlow, Mastra, Vercel AI SDK, OpenAI client, Chainlit.

### "Outer loop" concept (primary)
Source: `humanlayer.md` / `docs/core/outer-loop-agents.mdx` at `746df017`, and https://theouterloop.substack.com (second-hand link; not fetched).
- Gen 1 chat (human-initiated), Gen 2 agentic assistants (human-initiated, framework-driven), Gen 3 autonomous agents ("outer loop": agent-initiated contact with humans, triggered by cron/events). Needs: multi-channel contact (chat/email/SMS), cost inspection and a `sleep_until`, durable serialization across calls that return in hours/days, "manager LLM" context management, forkable sub-chains.
- "Function stakes" ladder in the README: low (public read, messaging the author), medium (private read, templated outbound), high (send on my behalf, write to private data). Approvals are described as "baked into the tool/function itself" so a hallucination cannot bypass them ("deterministically guarantee human oversight").

### A2H draft spec (unfinished)
`12-factor-agents/drafts/a2h-spec.md` (commit `dbf60d3`, 2025-06-29, "wip"): "A2H - The Agent-to-Human Protocol". Two scopes: agent side (request interaction) and optional admin side (manage humans/channels, so agents never see contact details). Objects `Message` and `NewConversation` with `apiVersion: proto.a2h.dev/v1alpha1`, `response_schema` (JSON Schema) for structured replies, `A2H_BASE_URL` / `A2H_API_KEY` env vars. Draft only; no later commits found.

## 2. CodeLayer (OSS IDE for Claude Code) and its successor

Two distinct things carry the name; keep them apart.

### 2a. OSS "CodeLayer" in `humanlayer/humanlayer` (deprecated; last tree `99abe673`)
Primary sources: https://github.com/humanlayer/humanlayer (files `hld/`, `hlyr/`, `humanlayer-wui/`, `claudecode-go/`, `docs/introduction.mdx`, `CLAUDE.md`), read at `99abe673`. License Apache-2.0. Releases: only nightlies/experimentals, latest `codelayer-0.1.0-nightly-20260227142452` (2026-02-27).

Architecture (from `CLAUDE.md`):
```
Claude Code -> MCP -> hlyr (humanlayer mcp claude_approvals) -> JSON-RPC (unix socket) -> hld -> (local SQLite)
                                                    ^ TUI   ^ WUI (Tauri + React)
```
- **hld** (Go): daemon. JSON-RPC 2.0 over Unix socket `~/.humanlayer/daemon.sock` (0600, line-delimited JSON, 1 MB buffer) AND an HTTP/REST + SSE server, default `127.0.0.1:7777` (`HUMANLAYER_DAEMON_HTTP_PORT=0` disables). REST is OpenAPI-generated (`hld/api/openapi.yaml`; 16+ endpoints: `/sessions`, `/sessions/{id}/continue|launch|interrupt|messages|snapshots`, `/sessions/archive|restore|search`, `/approvals`, `/approvals/{id}/decide`, `/stream/events` (SSE), `/slash-commands`, `/agents/discover`, `/fuzzy-search/files`, `/recent-paths`, `/config`, `/user-settings`, `/anthropic_proxy/{session_id}/v1/messages`). TypeScript SDK generated into `hld/sdk/typescript`.
- Daemon spawns Claude Code via `claudecode-go` (`client.go`): `claude --print --output-format stream-json [--verbose] --model ... --mcp-config <tmpfile> --permission-prompt-tool mcp__codelayer__request_permission --max-turns N --system-prompt/--append-system-prompt --allowedTools/--disallowedTools --add-dir ... --resume <id> [--fork-session] -- <query>`.
- **Approval flow**: hld injects an MCP server named `codelayer` (streamable HTTP, stateless, `X-Session-ID` header carries the hld session id) into every session's MCP config and sets `--permission-prompt-tool mcp__codelayer__request_permission`. Claude Code calls `request_approval/request_permission(tool_name, input, tool_use_id)`; the handler writes an `approvals` row (`pending`), publishes `new_approval` on an in-process event bus, and blocks on a Go channel keyed by `tool_use_id` until an `approval_resolved` event arrives; it then returns `{"behavior":"allow","updatedInput":...}` or `{"behavior":"deny","message":<comment>}`. No timeout ("we don't timeout approvals" comment). `MCP_AUTO_DENY_ALL=true` env for tests.
- Auto-resolution paths in `hld/approval/manager.go`: per-session `dangerously_skip_permissions` (approve everything), with optional `..._expires_at` (monitor goroutine polls every 30 s and disables it, emitting `session_settings_changed` with `reason=expired`; `humanlayer launch --dangerously-skip-permissions-timeout <minutes>`); per-session `auto_accept_edits` (approve `Edit`/`Write`/`MultiEdit` only).
- Event bus types: `new_approval`, `approval_resolved`, `session_status_changed`, `conversation_updated`, `session_settings_changed`; filter by event type, `session_id`, `run_id`; 30 s heartbeat on Subscribe.
- Session statuses: `draft`, `starting`, `running`, `completed`, `failed`, `interrupting`, `interrupted` (resumable), `waiting_input` (waiting on tool approval), `discarded`.
- **Session model** (SQLite `~/.humanlayer/daemon.db`, schema version 22): table `sessions` (id, `run_id` UNIQUE, `claude_session_id`, `parent_session_id`, query, summary, title, model/model_id, working_dir, additional_directories, max_turns, system prompts, allowed/disallowed tools, status, cost_usd, duration_ms, num_turns, detailed token fields, auto_accept_edits, dangerously_skip_permissions(+expiry/timeout), archived, proxy config); `conversation_events` (sequence, event_type message|tool_call|tool_result|system, role, content, tool_id/name/input_json, tool_result_*, `is_completed`, `approval_status` NULL|pending|approved|denied|resolved, `approval_id`, `parent_tool_use_id` for sub-task grouping); `approvals`; `mcp_servers` per session; `raw_events`; `file_snapshots` (content captured when the Read tool returns, used to render diffs for later Edit/Write); `user_settings` (singleton). "Continue" or "fork" creates a new hld session whose `parent_session_id` points at the old one (Claude `--resume` gives a new Claude session id), so history is a tree; list API defaults to leaf sessions.
- **Draft sessions**: sessions can exist in `draft` (configuration state) before launch (`/sessions/{id}/launch`, discard, hard-delete-empty).
- **Model proxy**: `/anthropic_proxy/{session_id}/v1/messages` lets a session send Claude Code traffic through hld to other providers (Baseten, OpenRouter code paths in `proxy.go`); per-session proxy URL/model/key columns; gated by user setting `advanced_providers`.
- **hlyr** (TypeScript CLI, npm `humanlayer`): `contact_human`, `mcp serve` (contact_human tool), `mcp claude_approvals` (the `request_permission` MCP tool bridging to the daemon over the unix socket with `HUMANLAYER_DAEMON_SOCKET` and session id from env), `launch` (see below), `thoughts ...` (section 4), `claude init` (copies `.claude/commands` + `agents` + settings into a repo; interactive select or `--all`).
- **`humanlayer launch`** options: `-m/--model`, `-w/--working-dir`, `--add-dir`, `--title`, `--max-turns`, `--no-approvals` (omits permission prompt tool), `--dangerously-skip-permissions`, `--dangerously-skip-permissions-timeout <min>`. Calls `launchSession` over the socket, prints session id and run id, then "use CodeLayer to manage this session". The team's own `/oneshot` command runs `humanlayer launch --model opus --dangerously-skip-permissions --dangerously-skip-permissions-timeout 14m --title "plan ENG-XXXX" "/oneshot_plan ENG-XXXX"` (a command that launches a fresh session running another command).
- **Worktrees**: no built-in management in the OSS app ("There's no built-in worktree management YET", `docs/introduction.mdx`); done via `hack/create_worktree.sh` (creates `~/wt/<repo>/<name>`, branch, copies `.claude/`, runs `make setup`, `humanlayer thoughts init` + `sync`; removes the worktree if setup fails) and `launch -w <dir>`. Per-branch dev daemon: each git branch gets its own daemon db/socket/port in dev mode.
- **WUI** (Tauri + React 19 + Zustand + Radix/shadcn + Tailwind; Rust daemon client in `src-tauri`; all data from the daemon, "purely a presentation layer"). UX primitives:
  - Session table with vim keys: `j/k` move, `shift+j/k` range select (anchor-based), `x` toggle select, `e` archive, `g>e` archived view, `g>s`/`g>i` inbox, `g>d` drafts, `z` undo (toast-based undo for archive/draft delete), `?` hotkey panel, `shift+tab` previous view mode (table tabs such as normal/archived/drafts), `meta+shift+j` jump to most recent pending approval (from toast `approval_required:*`), `alt+y` bypass permissions (for focused/selected sessions), `alt+a` enable auto-accept edits (also in session detail), `meta+k`/`ctrl+k` command launcher/session launcher.
  - Session detail: `j/k` move through conversation events, `a` approve the focused (or first pending) approval (first press scrolls to it if off-screen, second press approves), `d` start deny (opens response editor; deny requires a comment, sent with `cmd+enter`), `i` inspect tool result, `h/l` collapse/expand sub-agent (Task) groups, `u` jump to last user message, `p` navigate to parent session, `ctrl+x` interrupt, `alt+a` toggle auto-accept edits, `alt+y` bypass permissions, `y` copy. Hierarchical hotkey scopes (`*`, `.`, `sessions`, `sessions.details`, modals isolate root) via a scope manager.
  - Shows: conversation stream with tool calls grouped by sub-agent Task, per-event approval status, markdown with code, todo widget (TodoWrite), token usage badge and context gauge, model selector, status bar, tool-result modal, diffs from `file_snapshots`, fork modal (continue from an earlier event), draft launcher with `@` fuzzy file mentions and slash-command list (discovered from `.claude/commands`), additional directories.
  - Toasts and OS notifications for approvals; per-session response draft persisted in localStorage.
- **Parallel sessions**: any number of sessions run concurrently in one daemon (one `claude` subprocess each); the session table is the inbox; approvals from all sessions flow into one pending stream; keyboard jump to oldest/most recent approval. Marketing line: "M U L T I C L A U D E - run Claude Code sessions in parallel. Worktrees? Done. Remote cloud workers? You got it." (README at `HEAD~1`; worktrees/cloud were roadmap, not in the OSS code).
- Install (OSS era): `brew install --cask --no-quarantine humanlayer/humanlayer/codelayer` (unsigned). The app bundles `hld` and `humanlayer` binaries and starts/stops the daemon with the app. Telemetry: PostHog opt-in modal.
- Troubleshooting note in docs: missing `mcp__codelayer__approvals` tool means the `humanlayer` CLI binary is not on PATH.

### 2b. Current closed "HumanLayer" app (codename riptide), docs.humanlayer.com
Sources: https://docs.humanlayer.com (index, explanation/tasks, explanation/remote-daemons, explanation/workspace-model, reference/*, guide/*, release-notes), https://github.com/humanlayer/homebrew-humanlayer, https://github.com/humanlayer/humanlayer-pi, https://github.com/humanlayer/humanlayer-opencode.
- **Units**: *task* = group of sessions + shared task files + comments + history; *session* = one agent conversation (agent/model settings, working dir, messages, run state). Tasks are shared by default (0.162.0). Kanban columns: Todo/Draft, Research & Design, Planning, Implementation, In Review; list/board views, filters by owner/scope.
- **Task files**: directory `.humanlayer/tasks/<task-slug>/` in the worktree is a symlink to `~/.humanlayer/riptide/artifacts/...`. When the agent uses Read/Write/Edit/MultiEdit/apply_patch on a file there, the daemon syncs it to cloud (text artifacts md/mdx/txt/json/jsonl up to 10 MB; images/PDF/HTML via object storage). Cloud edits write back while sync is active. System prompt addition tells the agent the dir is a symlink, to use only edit tools (never bash/sed) so the UI sees changes, and offers a fenced block "```task-artifact <path>```" to inline-preview HTML/images.
- **Daemon**: desktop app starts a local daemon that launches Claude Code or Codex sessions; remote daemon = same on a Linux/Windows/other host: `npm i -g @humanlayer/cli`, `humanlayer login` (device-code; stores refresh token in `~/.humanlayer/riptide/`) then `humanlayer daemon launch`, or `daemon launch --launch-token <token>` (short-lived, exchanged for credentials of that process only). Sessions are controlled from `app.humanlayer.com` (browser/mobile) via an API; daemons stream events back to the API which streams to UIs. Update flow: app flags stale daemons (Online/Stale/Offline) and can push `npm install` of the matching CLI version; daemon exits with failure code so systemd restarts it. Doc supplies a systemd user unit and notes `loginctl enable-linger`.
- **Automation mode**: `humanlayer automation run --pat $HUMANLAYER_PAT --ensure-task <slug> --task-name ... --session-name ... --prompt-file ... [--shutdown-on inactivity|stop --inactivity 2m] [--provider --model --coding-agent --thinking]` starts an ephemeral daemon inside a CI job, runs one session in the job checkout with permission prompts bypassed, streams to cloud so humans can watch/follow up, exits with a code reflecting the session result. Documented GitHub Actions pattern: schedule trigger, no-op guard (`gh pr list --label <agent-label>`; one open agent PR at a time), concurrency group, agent memory file `.github/agent-memory/<agent>.md` included in the prompt, `/iterate` comment on the PR re-runs the agent on the same branch. Experimental ("ping founders@humanlayer.dev"), added 0.166.0.
- **Workspaces**: `.humanlayer/workspace.json` (shared, committed) merged with `.humanlayer/workspace.local.json` (gitignored). Fields: `disabled`, `setupBlocksFirstSession`, `pathTemplate` (default `~/.humanlayer/workspaces/{{ TASKSLUG }}/{{ REPOBASENAME }}`), `branchTemplate` (default `{{ TASKSLUG }}`, same for all repos), `sourceRef` (default `HEAD`; docs recommend `origin/main`), `setupCommand` (`sh -c` in each worktree after copying), `copyGlobs` (default `.env`, `.env.local`, `.env.development.local`, `.claude/settings.local.json`, `.humanlayer/workspace*.json`; append-and-dedupe only), `repos[] {localPath, description, sourceRef, setupCommand, copyGlobs, primary}` merged by `localPath`, local-only `$patch:"delete"`. Worktree timing per task: Now / Later (adds a `/rpi:create-worktree` phase) / Never. Workspaces pin to the exact commit of first successful setup (0.161.0). Multi-repo sessions get an injected `<workspace_information>` prompt block naming siblings; CLAUDE.md/AGENTS.md of every repo loaded (AGENTS.md preferred over CLAUDE.md for CodeLayer sessions).
- **Harnesses and models**: Claude Code (via Claude Agent SDK), Codex CLI, and "CodeLayer" (their own harness built on `agentlayer`; 0.144.0: "Claude Code is now the only supported harness for Anthropic models"), plus Copilot, Fireworks, Azure Foundry/custom Responses endpoints, Bedrock. Model picker names in notes include Claude Opus 5 / 5.5, Sonnet 5 / 5.5, Fable 5 / 5.1, GPT-5.6 Sol/Terra/Luna, GPT-6 Sol/Luna/Astra, GPT-6.1 Sol. **0.179.0 (2026-09-29): hand a session off from Claude Code to Codex or back; the new session continues on the same task and worktree with the full transcript.**
- **Sub-agent roster** (reference/subagent-models): `codebase-analyzer`, `codebase-locator`, `codebase-pattern-finder` (Sonnet, or Haiku via "Faster Research Subagents" experiment), `web-search-researcher` (Sonnet), `implementer-agent` (Sonnet), `implementation-reviewer` (Sonnet), `outline-implementer-agent` (`inherit` = parent model). ## 3. 12-Factor Agents

Sources: https://github.com/humanlayer/12-factor-agents (commit `d20c728`, last push 2025-09-21), `content/*.md`; https://www.humanlayer.dev/blog/12-factor-agents (2025-04-03). Talk: https://www.youtube.com/watch?v=8kMaTybvDUw (AI Engineer World's Fair, 17 min). 26.5k stars. License: code Apache-2.0, content CC BY-SA 4.0. Repo also contains `packages/create-12-factor-agent`, `packages/walkthroughgen`, `workshops/2025-05`, `2025-05-17`, `2025-07-16`, `drafts/a2h-spec.md`.

Core framing: an agent is a loop `context=[event]; while True: step = llm.determine_next_step(context); context.append(step); if done: return; result = execute(step); context.append(result)`. Claim: good production agents are mostly deterministic software with LLM steps at key points; take small modular concepts into existing products rather than adopt a framework.

| # | Factor | Mechanism (one line) |
|---|---|---|
| 1 | Natural language to tool calls | Convert a request into a structured object (JSON with intent + params) that deterministic code executes. |
| 2 | Own your prompts | Treat prompts as first-class code you write/version/test; don't hide them in a framework's `Agent(role, goal, ...)` black box. |
| 3 | Own your context window | Build the model input yourself (custom event/XML formats, not necessarily role/message arrays); "everything is context engineering": prompt, retrieved docs, history, memory, output schema. |
| 4 | Tools are just structured outputs | A tool is JSON the LLM emits (e.g. `CreateIssue`, `SearchIssues` with an `intent` field) that triggers ordinary code; results are appended to context. |
| 5 | Unify execution state and business state | Infer step/waiting/retry state from the event thread itself so one serializable thread gives resume, fork, debug, and UI. |
| 6 | Launch/Pause/Resume with simple APIs | Agents expose start/query/resume/stop; external triggers (webhooks) resume them; pause must be possible between tool selection and tool execution. |
| 7 | Contact humans with tool calls | Make `request_human_input` (with urgency, format yes_no/free_text/multiple_choice, choices) just another structured output; on it, save thread, notify human with thread id, break the loop, resume on reply. |
| 8 | Own your control flow | Write the `switch(intent)` loop yourself: break out to wait for a human on high-stakes calls, summarize/cache tool results, LLM-as-judge, compaction, rate limiting, durable sleep. |
| 9 | Compact errors into context window | On tool failure append a formatted error event and let the model retry; cap consecutive errors (e.g. 3) per tool and then escalate to a human. |
| 10 | Small, focused agents | Agents with 3 to 10 (max ~20) steps; larger tasks are composed of many small agents inside deterministic code; scope grows only as quality holds. |
| 11 | Trigger from anywhere, meet users where they are | Start agents from Slack/email/SMS/cron/events and reply in the same channel; enables outer-loop agents and higher-stakes tools via fast human loop-in. |
| 12 | Make your agent a stateless reducer | `(state, event) -> state`; the file contains only a stub ("mostly just for fun"). |
| 13 (appendix, "honorable mention") | Pre-fetch all the context you might need | If a tool call is highly likely (e.g. list git tags before deploy), run it deterministically and put the result in the prompt instead of paying a model round trip. |

Related primary claim: "context engineering" term attributed by HumanLayer to Factor 3 (April 2025). The repo's related-resources list originally pointed at `kubechain` (a "framework for running distributed agents in kubernetes", i.e. ACP's former name; repo created 2024-10-17, see section 5).

### 4b. ACE-FCA mechanism (2025-08, primary: ace-fca.md at `f2bc7ae`)
- Claim: LLM turns are stateless functions; only the context window affects output quality. Optimize for correctness, completeness, size, trajectory. Worst failures, in order: incorrect information, missing information, too much noise.
- Intentional compaction = pause and write progress (goal, approach, steps done, current failure) to a file (`progress.md`) or commit message, restart in a fresh window. "What eats context": file search, code-flow understanding, edits, test/build logs, large tool JSON.
- **Frequent intentional compaction**: design the whole workflow around context, keep utilization in the 40 to 60% range; three (-ish) phases, each a separate context window ending in a compact artifact: Research (how the system works, relevant files; objective), Plan (exact steps, files, per-phase test/verification), Implement (phase by phase; compact status back into the plan file after each verified phase). Worktrees are only needed for implement; research/plan happen on main.
- Sub-agents are "about context control, not roles": a fresh window does the find/search/summarize and returns a compact answer.
- Human leverage argument: a bad line of research can cause thousands of bad lines of code, a bad plan line hundreds, so review research and plans rather than code; "I can't read 2000 lines of Go daily but I can read 200 lines of a plan." Mental alignment across the team is the purpose of review.
- Numbers quoted: BAML (300k LOC Rust) bug fix PR approved next morning; 35k LOC (cancellation + WASM) shipped in 7 hours (3 h research/plan, 4 h implement) vs 3 to 5 days estimated each; team of three averaged about $12k/month on Opus; context "170k window" quote from Geoff Huntley; Ralph loop `while :; do cat PROMPT.md | npx @sourcegraph/amp; done`.
- Failure disclosed: parquet-java Hadoop-removal attempt did not work (research did not go deep enough through dependency tree).

### 4c. What changed 2026 (primary: talk transcript YwZR6tc7qYg, wsff.md, docs.humanlayer.com)
Self-reported failures of RPI at scale (thousands of engineers since Oct 2025):
1. Research polluted by the ticket: if the model knows what you're building it returns opinions. Fix: one context window generates questions from the ticket; a fresh window with no knowledge of the ticket answers them (deterministic ticket hiding).
2. Planning prompt was one monolith with ~85 instructions; ~50% of runs skipped the interactive steps (design options, outline approval) and wrote the plan directly ("magic words" problem: "work back and forth with me starting with open questions and outline"). Cited "instruction budget": frontier models follow roughly 150 to 200 instructions consistently (arXiv 2507.11538 per the blog); system prompt + CLAUDE.md + tools + MCP all count. Fix: split into prompts each under 40 instructions; "don't use prompts for control flow if you can use control flow for control flow".
3. A 1,000-line plan ~ 1,000 lines of code, so reading it is not leverage and plans have surprises. New advice: read the code, not the plan; review shorter artifacts earlier.
4. Models write horizontal plans (DB, then service, then API, then UI). Fix: structure outline of vertical slices/tracer bullets with a testable result per phase.
5. Reversal: Aug 2025 "don't read the code" -> 2026 "please read the code"; a lights-off factory run for about 5 months produced unmaintainable code and parts were ripped out.

New pipeline names: **QRSPI** (Questions, Research, Design, Structure, Plan, Worktree, Implement, PR; nicknamed "CRISPY"; informal acronyms vary across second-hand summaries). Targets 2 to 3x speedup, not 10x.
- Design discussion (~200 lines): current state, desired end state, patterns to follow, resolved decisions, open questions; human edits it to "do brain surgery on the agent before downstream".
- Structure outline (~2 pages vs 8-page plan): "C header file" of phases, signatures, new types, vertical slices, test points.
- Plan: tactical doc for the agent; only spot-checked.
- Alignment checkpoints are author-opt-in: author picks the reviewer and walks them through product/tech docs.
- "Software factories fail" essay (wsff.md): front-load alignment in 4 phases (product review, system architecture, program design = types/signatures/call stacks/file-tree diffs, vertical slices); estimated task mix ~40% one-shot with 1-2 light rounds, medium = product+system design in one doc without phases, large = all steps; send a model off for 1-3 slices at a time and review as you go. Argument that models degrade maintainability because RL rewards "tests pass" and nothing penalizes bad design; SlopCodeBench results (Opus 5 24% strict on a 17-checkpoint subset vs 17% for Opus 4.6 in the paper).
- Other published idioms: `<important if="...">` conditional blocks in CLAUDE.md (https://www.humanlayer.dev/blog/stop-claude-from-ignoring-your-claude-md; skill `improve-claude-md`); CLAUDE.md "under 60 lines"; context-efficient backpressure (`run_silent` wrapper prints a check mark on success and full output only on failure, fail-fast flags; `hack/run_silent.sh`) https://www.humanlayer.dev/blog/context-efficient-backpressure; ~75k-token "smart zone" for Claude models; context forking (rewind to a user-turn boundary and branch) https://www.humanlayer.dev/blog/context-forking-to-save-time-trouble-and-tokens; "long context isn't the answer" (reverted from Opus 4.6 1M to 4.5, context warning fixed at 100k tokens) https://www.humanlayer.dev/blog/long-context-isnt-the-answer; sub-agents as "context firewall" and a `subagent-orchestrator` skill; prefer CLI wrappers over MCP servers (they wrote a small `linear` CLI rather than use the Linear MCP).

### 4e. `thoughts/` directory convention (primary: `hlyr/src/commands/thoughts/*.ts`, README)
- Purpose: keep notes/plans/research out of the code repo but visible to agents.
- A separate git repo (default `~/thoughts`, with `repos/` and `global/` subdirs, user name chosen at init) holds the content. `humanlayer thoughts init` creates in the code repo a `thoughts/` directory of **symlinks**: `thoughts/<user>/` -> `<thoughtsRepo>/repos/<repoName>/<user>` (personal), `thoughts/shared/` -> `.../repos/<repoName>/shared` (team), `thoughts/global/` -> `<thoughtsRepo>/global` (cross-repo, with `<user>/` and `shared/`), plus symlinks for other users.
- `thoughts/searchable/` = **hard links** to every file reachable through the symlinks (rebuilt by `humanlayer thoughts sync`), so grep/glob tools that don't follow symlinks can search; agents are told to cite canonical paths (strip only `searchable/`).

Installs git hooks in the code repo: `pre-commit` (blocks staging anything under `thoughts/`; hook version 3) and `post-commit` (auto `humanlayer thoughts sync --message "Auto-sync with commit: <msg>"` in background; skipped in git worktrees to avoid repository-boundary confusion).

Status: described by HumanLayer as "v0 janky prototype"; docs say proper support is "coming to CodeLayer"; superseded in the current product by `.humanlayer/tasks/<slug>/` cloud-synced artifacts (section 2b).

## 5. Agent Control Plane (ACP) and other repos

### 5a. ACP (Kubernetes operator)
Sources: https://github.com/humanlayer/agentcontrolplane (commit `eaa2a7e`, 2025-07-02), README, `acp/api/v1alpha1/*.go`, `acp/docs/*`. Apache-2.0. Alpha. Repo created 2024-10-17 (as "kubechain"; the 12-factor README still links `humanlayer/kubechain`); last commit 2025-07-02; CHANGELOG top entry v0.5.1 (2025-04-17); not archived; 496 stars. No new commits in 15 months.
- Pitch: "distributed agent scheduler ... for outer-loop agents that run without supervision, and make asynchronous tool calls like requesting human feedback."
- CRDs (`acp.humanlayer.dev/v1alpha1`): `LLM` (provider + secret ref + params; OpenAI, Anthropic, Vertex, Mistral), `Agent` (llmRef + system prompt + `mcpServers` + `subAgents` + `humanContactChannels`), `MCPServer` (stdio/http transport; `approvalContactChannel` makes every tool of that server wait for human approval), `Task` (agentRef + userMessage; `status.contextWindow` holds the whole conversation, `status.output` the answer), `ToolCall` (one per tool call), `ContactChannel` (`type: slack|email`, `apiKeyFrom` secret ref to HumanLayer API key, slack `channelOrUserID` pattern `^[CU][A-Z0-9]+$`, `allowedResponderIDs`, email `address/subject/contextAboutUser`).
- State machine in phases: Task `Initializing, Pending, ReadyForLLM, SendContextWindowToLLM, ToolCallsPending, CheckingToolCalls, FinalAnswer, ErrorBackoff, Failed`. ToolCall `Pending, Running, Succeeded, Failed, AwaitingHumanInput, AwaitingSubAgent, AwaitingHumanApproval, ReadyToExecuteApprovedTool, ErrorRequestingHumanApproval, ErrorRequestingHumanInput, ToolCallRejected`. Controllers per kind in `acp/internal/controller/`. History is Kubernetes Events (`ToolCallsPending`, `ToolCallCreated`, `AllToolCallsCompleted`, `SendingContextWindowToLLM`, `LLMFinalAnswer`).
- Human approval and human-as-tool go through the HumanLayer cloud API (needs `HUMANLAYER_API_KEY` secret); README notes approving directly via kubectl/CLI is "planned but not yet supported". Delegation to sub-agents is a tool type (task phase `AwaitingSubAgent`).
- Concurrency: dual-layer locking: in-process mutex per task plus Kubernetes `Lease` objects so multi-pod reconcilers do not duplicate LLM calls (`acp/docs/distributed-locking.md`).
- Design principles in README: simplicity (the call stack is the rolling context window, "no separate execution state", i.e. Factor 5), clarity, control, modularity (small control loops), durability, extensibility (agents are YAML).

- **fold** (https://github.com/humanlayer/fold, MIT, created 2026-07-01, active): Effect-native, provider-agnostic, isomorphic agent core. Packages `fold-core` (log-based state, tool/hook support, subagents and skill facades, event streaming, auto-compaction, session management), `fold-agent` (built-in profiles, tools read/write/edit-or-apply_patch/bash/skill/agent/web_search/web_fetch; tool set reselected per active model: Claude gets write/edit, GPT/Codex gets apply_patch), `fold-cli` (TUI `foldcode`, headless `--prompt`), providers for Codex, OpenCode Zen, xAI. JSONL event log (`jsonlEventLog('.fold/review.jsonl')`). Described as supporting "RLM-like orchestration patterns". In the app it is the "Fold coding agent" experiment (0.169.0 Grok support; "tool delegation and fork history", 0.165.0).
- **agentlayer** (https://github.com/humanlayer/agentlayer, MIT, created 2026-04-02): Bun monorepo; `agentlayer-core` = "resumable agent loop (Vercel AI SDK `streamText`) with tool-interface/executor separation, approval hooks, stop conditions"; executors for filesystem, `just-bash` virtual bash, Yjs CRDT-backed collaborative filesystem (`yjs-fs` with comments and live-cursor presence; `yjs-fs-secure-exec` sandboxed Node); providers for GitHub Copilot, OpenAI Codex (ChatGPT OAuth), vendored OpenCode LLM client; agents `codelayer` ("multi-provider coding agent CLI with RPI-style sub-agent orchestration") and `docs-agent` (CI agent that updates AgentLayer docs on PRs). External PRs require a "vouch" from a maintainer via Discord.
- **effect-channels** (https://github.com/humanlayer/effect-channels, MIT, created 2026-08-29): inbound Slack and GitHub webhooks into durable per-thread "mailboxes". Flow: `POST /integrations/:integration/webhook` -> verify signature + parse -> `MailboxDelivery` saves event (dedupes) in a mailbox (one Slack thread or one GitHub issue/PR) -> `MailboxProcessing` claims a batch -> user callback -> result saved; retryable failure reruns the same batch. One batch at a time per mailbox (ordered), different mailboxes concurrent; at-least-once; claim by "events up to number N" so late arrivals wait for the next batch; lease (`leaseMs` 30 s, renewed while callback runs), `maxAttempts` 5, `concurrency` 8. Delivery modes: `Queue` (run immediately, all waiting events), `Serial` (one event, oldest first), `Debounce` (`quietPeriodMs`, `maxWaitMs`), `Burst` (`windowMs` after first event); no default. Slack handlers `onNewMention` (not yet subscribed thread; `thread.subscribe()`, `startTyping()`, `post()`), `onSubscribedThreadEvents`; GitHub handlers `onIssueCreated`, `onPrCreated`, `onMentioned`, `onSubscribedIssueEvents`, `onSubscribedPrEvents`; storage backends Postgres (polling 1 s), Redis, in-memory, Cloudflare Durable Objects (one DO per mailbox, alarm-woken). Explicitly "no universal provider facade and no agent engine".
- **effect-machine**: typed state machines/actors on Effect (states and events are schemas). **ampere**: "TypeScript + Effect State Machine WAL parser" (README one line). **effect-durable-streams** (+ client): server for the Durable Streams protocol (node host and Cloudflare Durable Object host; shared conformance suite).
- **skills** (https://github.com/humanlayer/skills, MIT): `show-me`, `visual-pr`, `improve-claude-md`, `narrow-react-prop-types`, `build-iterated-agentic-loop`, `design-control-loop`. `design-control-loop` frames a scheduled coding-agent workflow as set point / sensor / controller / actuator under disturbances with a memory file and optional "dampener" regression gate; `build-iterated-agentic-loop` scaffolds `.claude/skills/<name>/SKILL.md` + `.github/workflows/agent-<task>.yml` + `.github/agent-memory/<task>.md`, label-bounded to one open PR per loop (default), PR title template `[MM/DD][Agent: <Name>]: <desc>`, optional `/iterate` PR comment handler script (`agent-iteration.ts` with `footer` and `prompt` modes). `visual-pr` writes a PR body with one-sentence "Why", 1-3 "Special things to note", and a compact "Change outline" (SQL/endpoint contracts, types, shallow file tree, component tree, call tree) saved to `.humanlayer/tasks/<slug>/pr-description.md`.
- **homebrew-humanlayer**: casks `humanlayer`, `humanlayer-beta`, `humanlayer-dev`, `humanlayer-electron*`, plus legacy-named `riptide*`; current 0.180.0 DMG `Riptide-darwin-arm64.dmg`.
- Forks/infra: `electric` (fork of ElectricSQL; description "The agent platform built on sync"; README unchanged from upstream, so intent unverified), `react-hotkeys-hook` (fork, used by the WUI), `ghostty-web` (archived fork), `distilled`, `pulumi-resend`, `pulumi-stripe`.
- Private (not inspectable): `humanlayer/synclayer` (monorepo behind the current app, referenced by the opencode plugin README); `packages/ui/src/constants/rpi-skills.ts` and `apps/riptide-rpi-claude-plugin/skills/` referenced by docs.
