## Findings

### MEDIUM

#### 1. Same-session provider reservations can escape onto different pool runners

- Reviewer: `andthen-review-critic`, validated by main rereview.
- Severity: MEDIUM.
- Confidence: 100.
- Location: `packages/dartclaw_server/lib/src/turn_manager.dart:457`.
- Scope relation: primary – the completed plan changes this provider-pinned pool-routing seam and must preserve the existing same-session serialization contract.
- Finding: `_reserveRunnerForSession` checks `_providerSessionRunners[sessionId]` before awaiting session lookup and provider provisioning. Two concurrent reservations can both observe no binding, acquire different matching runners, then overwrite the shared runner/reservation maps.
- Threatened assumption or invariant: all turns for one session must share one runner and its `SessionLockManager`, provider continuity, and ordered message path.
- Evidence: the binding is read at lines 458–462, but not published until lines 482–483 after `getSession()` and, with the coordinator, `provisionAndAcquireProvider()`. Both calls can pass the initial read and acquire separate idle/spawned runners. Existing concurrency tests cover same-session locking inside one runner, not acquisition of the runner binding itself.
- Impact: same-session turns can execute concurrently on separate harnesses, producing out-of-order persistence, conflicting provider history, or a false pool-unavailable result instead of queuing behind the active turn.
- Suggested fix: coalesce acquisition per session or publish an in-flight session-binding future before awaiting provisioning; every concurrent reservation for that session must await and reuse the same runner.
- Verification needed: start two simultaneous reservations for one provider-pinned session with two matching idle/spawnable runners; prove both bind to one runner and the second waits on the same session lock.
- Class: code-defect.
- Routing: Fix – confidence is 100, scope is primary, and the required serialization invariant uniquely determines the bounded correction.
