## Summary

QMD remains the shipped opt-in semantic-memory provider. The 2026-07-25 research and spike established an in-process embedding path through `llamadart`; their resource measurements remain historical evidence, not promises about a new dependency version. Phase B composes Phase A's `FullTextIndex` with a new `VectorIndex` and an `EmbeddingProvider` seam plus weighted RRF in the ADR-050 `dartclaw_search` package. The target is built-in, local-first hybrid search with no Node process in that path. LLM query expansion and cross-encoder reranking remain excluded; the held-out evaluation below must prove the resulting pipeline.

## Gates (before full PRD / plan)

1. **Validation spike – RUN 2026-07-25, PASSED** (full record incl. reproduction: [spike-llamadart-embeddings.md](../../research/dart-native-hybrid-search/spike-llamadart-embeddings.md); throwaway code retained locally outside version control per spike discipline). Results:
   - **macOS arm64 AOT**: `dart build cli` end-to-end works; bundle = 6 MB bin + 10 MB `libllamadart.dylib` (ADR-048 shape); max RSS ≈ 477 MB with model resident; ~7 ms/doc embed (post-load); model load 7.4 s (Metal warmup).
   - **Linux arm64 AOT (Docker dart:stable, historical run)**: worked; model load 166 ms, ~31 ms/doc CPU. **Two findings**: (a) Linux bundles needed `libgomp1` at runtime – verify and document/bundle for the selected release artifacts; (b) llamadart hung indefinitely when the native lib failed to load – the implementation needs bounded initialization with proven failure handling. Linux x64 and Windows legs remain required, pending evidence; lack of that evidence prevents release acceptance.
   - **Parity**: cosine 1.000000 (×4 texts) vs llama.cpp's own `llama-server` on the same GGUF.
   - **Retrieval fixture** (24 docs, 16 queries, sv+en): keyword-only 0.38 hit@1 (0.00 on sv-inflection/compound/vocab-mismatch – the motivating gap); embeddinggemma-300M vector **1.00/1.00**; hybrid RRF 0.94 (one query where noisy keyword matches dragged fusion below pure vector – tune weights at spec time). **Qwen3-Embedding-0.6B head-to-head: 0.94/0.94**, missed the hardest Swedish vocab-mismatch query, weaker cross-lingual cosine (0.62 vs 0.80), 2× size – **embeddinggemma-300M stays the default candidate** despite SEB (where base gemma is only partially evaluated; its Scandi finetune ranks #51 ret-mean 54.52 vs qwen3 #21 ret-mean 61.85 – small fixture vs board data tension recorded; revisit with a larger eval at spec time).
   - **Supply chain**: bundles from `github.com/leehack/llamadart-native` releases, tag pinned in the hook (b10075); overrides exist and work (`hooks.user_defines.llamadart`: `llamadart_native_tag`/`_repository`/`_path`, `llamadart_native_runtimes` – restricting to `[llama_cpp]` trims the Linux lib/ from 194 MB to 98 MB; further backend trim of the 40 MB Vulkan lib via `llamadart_native_backends`, untested). **llama.cpp archives are tag-pinned but not sha256-verified by the hook** (only LiteRT archives are) – release builds should mirror bundles or use the local-path override.
2. **ADR – DONE 2026-07-25**: public **ADR-050** (Accepted; supersedes ADR-004, records the Phase-3 delivery against ADR-045, encodes the three owner decisions). **Both gates are satisfied** – the full Phase B PRD can be written at planning time.

## Proposed Scope

- **`dartclaw_search` package**: preserve ADR-050's accepted package boundary and inject concrete indexes. Ports belong in the landed kernel contract layer. At Phase B planning, record an ADR-050/056 alignment amendment and an explicit package-count/tier change for this new package; Phase A's existing ceiling is not permission to add it early. Use the current tier mechanism, not a resurrected per-edge allowlist. Determine placement from the actual imports, with no driver dependency in the search package and no production edge from core to it.
- **`EmbeddingProvider` seam, two implementations**: `LlamaEmbeddingProvider` (in-process llamadart; default model embeddinggemma-300M Q8_0, 768-dim, pinned GGUF URL + checksum, one-time download honoring the network-gating posture) and `OpenAiCompatibleEmbeddingProvider` (HTTP base URL + optional API key – covers llama-server/Ollama/LM Studio locally and cloud endpoints as documented opt-in).
- **`VectorIndex` implementations**: SQLite = float32 BLOB storage + brute-force cosine in Dart, with no vector extension; PostgreSQL = `pgvector` (former ADR-045 Phase 3). Phase B introduces the port and implementations. Extend the landed current-schema bootstrap and required-object manifests; specify extension provisioning, permissions and actionable refusal explicitly. No migration runner is introduced, and extension failure must not leave a partially initialized authoritative store.
- **`HybridSearchBackend`** behind the existing `SearchBackend` contract: Dart-side weighted RRF (k=60, identical constants both backends; in-database PG fusion recorded as later optimization); embed-on-write with keyword-only degradation when the embedder is unavailable (loud log + visible unembedded counter, never a hard error); content-hash + embedder-fingerprint incremental re-embedding (QMD pattern – model/chunk-param change invalidates and re-embeds the delta only).
- **Explainable retrieval + per-turn trace**: an opt-in diagnostic shape exposes each returned result's keyword rank, vector rank, RRF contribution/fused score, source layer/tier, and any keyword-only degradation. Normal agent payloads stay compact; diagnostics and the existing turn-trace surface retain the source locators actually returned so an operator can answer "why did this memory surface?" without reproducing the query against mutable state.
- **Chunker**: heading-scored, code-fence-safe break-point chunking as the single owner of memory chunk identities for incremental indexing and rebuild. Inspect the landed projection before replacing its implementation; do not assume the old live-write/rebuild split still exists.
- **Deterministic memory projection**: inherit Phase A's validated searchable canonical roles, currently topic, archive, observation and learning. The canonical index, deletion audit and error role remain outside searchable content; daily-log filenames do not independently confer search eligibility. Preserve source identity, tenancy and provenance. Incremental writes and `rebuild-index` must produce the same identities/chunks/result membership, including clearing stale rows when the searchable corpus is empty. Resolve this against the actual corpus mapper rather than the obsolete `MEMORY.md`-only rebuild description. Wiki and authoritative KG search remain separate layers.
- **Config**: `search.backend: hybrid` + `search.embedding.*` (provider/model/endpoint/api_key per research §5.8; credential-reference model for keys).
- **QMD deprecation begins**: `backend: qmd` config warning at Phase B GA; removal (QmdManager/QmdSearchBackend/factory branch/docs) one milestone later.
- **Quality acceptance**: promote the spike's 24-document/16-query fixture from calibration evidence into a committed, privacy-safe, held-out Swedish+English retrieval suite with sealed judgments and at least 50 queries across exact-keyword, vocabulary-mismatch, named-entity, temporal, relational, and no-result families. Report backend-native keyword/vector/hybrid hit@1, recall@5, precision@5, MRR, and p95 latency; preserve the shipped invariant that synthesized wiki sources outrank raw memory for the same topic. Hybrid must beat keyword-only on vocabulary mismatch and stay within a predeclared tolerance of the better constituent on every other family – recall alone is not a release claim.
- **Docs**: user-guide search page (incl. cloud-opt-in trust-boundary caveat + per-language behavior: embeddings sidestep stemming; keyword stemming stays backend-specific), architecture doc sync, ADR-004 status update, glossary entries.

## Non-Goals

- LLM query expansion and cross-encoder reranking (deliberate exclusion – research §5.9; the typed sub-query fusion seam keeps the door open; future path is on-demand rerank via existing LLM harnesses, no resident models).
- SQLite vector extension (sqlite-vec / sqlite_vector) – brute force suffices at corpus scale.
- QMD *removal* (deprecation only in this phase; removal one milestone later).
- Convex-combination scoring (upgrade path once relevance-judgment data exists).
- Cloud embeddings as *default* – local stays default; cloud is documented opt-in only.
- A general knowledge graph or LLM entity/link extraction. Deterministic adjacency boosting from explicit Markdown links and existing `related:` metadata is a **conditional follow-on spike**, triggered only if the Phase B retrieval suite demonstrates a material relational-query gap; it is not committed Phase B scope and adds no graph database.

## Dependencies & Planning Checks

- **Hard prerequisite**: Phase A accepted on the integration branch, with its actual `FullTextIndex` and current-schema gate available. Phase B's production implementation follows that checkpoint; evaluation preparation and platform feasibility work can proceed earlier. No separate owner instruction to begin Phase B is required by the execution strategy.
- Contract placement: `FullTextIndex` is delivered by Phase A in `dartclaw_kernel`; Phase B adds `VectorIndex` at that same contract altitude. Concrete database implementations remain in `dartclaw_core`. The retired `dartclaw_storage` package is not a dependency or placement option.
- Corpus boundary: Phase A defines `FullTextIndex` as a generic lexical-document port. It now has **two** instances – memory and the conversation-message corpus (FR11 rider, owner 2026-08-07). Phase B may compose the memory instance with `VectorIndex`; it must not absorb authoritative temporal-KG facts, live wiki files, or tasks into the same projection without a separate requirements decision.
- Conversation-corpus hybrid (owner execution instruction, 2026-09-08): FR11/S13 supplies lexical conversation search; Phase B must add a second `VectorIndex`/hybrid instance over the same seams for conversation messages as well as memory. Preserve each corpus's tenancy, source locators, deletion and rebuild lifecycle. The held-out suite must report both corpora; sizing pressure does not authorize dropping conversation hybrid search.
- llamadart: pin exact version; mirror/vendor prebuilt bundles for `network: disabled` builds; single-maintainer risk is accepted *because* the `EmbeddingProvider` seam keeps it swappable.
- Default-model confirmation: embeddinggemma-300M vs qwen3-embedding-0.6B (32k ctx, better raw multilingual score) – decided by the spike's SEB pull + fixture results.
- Decided posture (owner, 2026-07-25 – binding, research §8): documented cloud opt-in **accepted**; QMD **deprecate-then-remove**; **one binary, all-in** (no build flavor; jointly resolved ADR-045 OQ3).
- Sizing: target ≤ 10 stories. The held-out release gate and opt-in retrieval explanation are load-bearing, not split targets. If sizing runs over: cloud-provider documentation polish first, optional replay/UI breadth second, chunker adoption for non-memory corpora last (memory corpus is the v1 target).

## Success Criteria (sketch)

- Semantic Swedish/English memory search works after one pinned model download – no Node, no npm, no external process, on both DB backends.
- Held-out suite reports the five named quality/latency metrics for backend-native keyword, vector, and hybrid retrieval; hybrid improves vocabulary-mismatch retrieval, does not exceed the predeclared per-family regression tolerance against the better constituent, and preserves wiki-over-raw ranking; set-membership contract tests pass on both backends.
- An operator can inspect why each hybrid result surfaced and which source locators were returned to a turn without inflating normal agent search payloads.
- Embedder unavailable ⇒ keyword-only degradation with loud logging and a visible unembedded count – never a hard failure, never silent.
- `backend: qmd` still works through the deprecation window with a visible warning; `rebuild-index` re-embeds incrementally (unchanged content not re-embedded).
- After any rebuild, the memory projection has the same document identities, chunks, and result membership as the equivalent incremental write/prune history; an empty canonical corpus leaves an empty projection; the full PRD explicitly resolves archive and daily-log inclusion.
