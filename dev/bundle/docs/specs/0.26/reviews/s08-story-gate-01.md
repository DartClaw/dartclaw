### F01 – URI-equivalent inline passwords bypass the load-time persistence refusal

- Reviewer: Code + Gap + Critic
- Severity: HIGH
- Confidence: 100
- Location: `packages/dartclaw_kernel/lib/src/config_parser_providers.dart:47`
- Scope relation: primary
- Finding: `_persistedDatabaseSecretShape` recognizes userinfo only when the raw value begins exactly with `postgres://` or `postgresql://`, and recognizes the query key only when its raw spelling is exactly `password`. A quoted value with leading whitespace, such as `" postgresql://runtime:LiteralPasswordX9@database.internal/app"`, or a URI-equivalent encoded query key, such as `?pass%77ord=LiteralPasswordX9`, therefore produces no persisted-secret warning at configuration load.
- Threatened assumption or invariant: S01(h), OC01, and SC05 require every persisted `database.url` containing a literal userinfo password or `password=` query parameter to refuse at load based on the raw template, before substitution or connection work.
- Evidence: The authority regex is anchored at `^postgres` without normalizing surrounding whitespace, and the query loop compares the undecoded raw key to `password`. For either input, `hasUrlReference` is true while `persistedSecret` remains null, so the `backend == postgres` branch emits no warning. `postgres_connection_posture.dart` may reject these values later, but that does not satisfy the specified load-time persistence guard. `packages/dartclaw_kernel/test/database_config_test.dart:92` covers only canonical spellings, so both bad states still pass the proof suite.
- Impact: A PostgreSQL configuration can retain a literal password in `dartclaw.yaml` without the blocking warning and reference-model remediation promised by the story. Startup later fails, but the secret has already bypassed the configuration boundary designed to keep usable credentials out of persisted config.
- Suggested fix: Normalize only for detection before matching the URI prefix, decode query keys before comparing them to `password` with malformed encoding handled as a safe refusal, and add table cases for quoted leading whitespace and percent-encoded `password` keys. Keep the original raw template for environment-reference provenance and diagnostics.
- Verification needed: Run the focused kernel database-config test and assert both variants add a blocking warning naming `database.url`, environment substitution, and `database.credential`, without reproducing the fixture password; retain the existing environment-only and inactive-SQLite cases.
- Class: code-defect
- Routing: Fix – the FIS explicitly binds load-time refusal and the parser/test correction is bounded and decision-free.
