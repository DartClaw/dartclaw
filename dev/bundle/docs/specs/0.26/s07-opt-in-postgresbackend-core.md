## Feature Overview and Goal

**Intent**: Stories S01–S06 put every authoritative and derived store behind the `DatabaseBackend` seam on SQLite only; this story lands the smallest production PostgreSQL core behind that same seam – typed selection, one bounded pool, exact current-schema bootstrap and validation, the pinned transaction contract, and failures that neither replay uncertain work nor expose connection secrets – so S08–S11 can harden, search-enable, interlock, and contract-test a backend that already exists.

**Expected Outcomes**:

- [OC01] `database.backend: postgres` with a resolvable `url` opens one PostgreSQL database through one pool, prepares the exact current schema before any repository is constructed, serves the seam-backed relational stores, and closes the pool exactly once at shutdown.
- [OC02] Omitting `database:` (or selecting `sqlite`) keeps the released-0.25 SQLite behavior with no PostgreSQL connection, file, log line, or test dependency.
- [OC03] PostgreSQL `transaction()` honours the S01 contract: atomicity and rollback, zone-matched owner operations join the leased connection, nested `transaction()` rejects with `NestedTransactionError`, transaction-bound statements expire, and concurrent operations run on other pool connections without observing the open transaction.
- [OC04] Connection handling is bounded and explicit: only failures proven to occur before dispatch retry (to a fixed bound); a transport loss after dispatch or an ambiguous commit surfaces `StorageUnknownOutcomeException` after exactly one dispatch; pool waits end in a typed error, never a hang.
- [OC05] Incompatible PostgreSQL schemas, unsupported server versions, and operational failures refuse before repository use with typed, redaction-safe messages that never carry the DSN or raw driver text.

- **S03 [OC03] [TI01,TI05] [runtime] Transactions satisfy the S01 contract on a real pool**
  - **Given** an open `PostgresBackend` with `pool_size` ≥ 2 and a `transaction()` body that (a) commits, (b) throws after writing, (c) calls `transaction()` again on `tx` and on the owner and catches the error, (d) writes through the owner backend and an owner-prepared statement from inside the body, (e) prepares a statement through `tx`, (f) signals the test mid-body through a `Completer` so the test issues a concurrent owner `execute` from outside the zone
  - **When** each body runs
  - **Then** (a) commits and returns the body's value; (b) rolls back every write and rethrows; (c) each nested call threw `NestedTransactionError` promptly and the outer transaction still commits; (d) the zone-matched owner writes vanish with the rollback; (e) the `tx`-prepared statement rejects `execute`/`query` with `StateError` after completion and closes twice without error; (f) the concurrent write persists on another connection, completes without waiting for the body (asserted as completion ordering), and never observed the uncommitted rows

- **S04 [OC04] [TI04,TI05] Retry stops at the dispatch boundary**
  - **Given** a deterministic driver seam that fails (a) connection acquisition or handshake before any operation is sent, (b) the transport after a query was sent, (c) the transport after `COMMIT` was sent, or (d) with a server error response carrying a SQLSTATE
  - **When** the backend executes the operation
  - **Then** (a) retries within the fixed attempt bound and succeeds when the seam recovers, or throws `StorageConnectionException` when the bound is exhausted; (b) and (c) dispatch exactly once, never retry, and throw `StorageUnknownOutcomeException`; (d) dispatches once and throws `StorageQueryException` carrying the SQLSTATE; the dispatch count is asserted in every case

- **S05 [OC01,OC05] [TI06] [runtime] Schema preparation is atomic and exact**
  - **Given** (a) a failure injected after each DDL statement of fresh bootstrap through the S02 test-only failing decorator, (b) a database already at epoch `1` with every required object, (c) a non-empty database with no `dartclaw_schema` table, (d) epochs `0`, `2`, an empty or duplicated marker, or a non-integer epoch, and (e) epoch `1` with a required table, column (name, type, nullability, primary-key membership), or index missing or mismatched
  - **When** `PostgresSchemaGate.prepare` runs
  - **Then** (a) the catalog holds no DartClaw object after rollback and a clean retry on the same backend converges; (b) performs no write (catalog snapshot and `pg_stat` write counters unchanged); (c), (d), and (e) throw `SchemaIncompatibleException` before any repository is constructed, naming the database by its safe identity, stating expected versus found epoch and the structural differences, and directing the operator to back up then reset/recreate for this release, with the catalog unchanged; an unmarked PostgreSQL database has no adoption path

- **S06 [OC04,OC05] [TI04,TI05] [runtime] Pool pressure, unreachable servers, and unsupported versions terminate safely**
  - **Given** (a) `pool_size` connections all leased by open transaction bodies and one more operation issued, (b) a `url` whose host refuses connections, and (c) a reachable server reporting `server_version_num` below 140000
  - **When** the operation or `PostgresBackend.open` runs
  - **Then** (a) the extra operation waits at most the fixed pool-wait ceiling then throws `StoragePoolExhaustedException`, and completes normally when a lease is released within the ceiling; (b) `open` throws `StorageConnectionException` after the fixed attempt bound and leaves no open socket or pool; (c) `open` throws `StorageConnectionException` naming the required major version and closes the connection it probed with

- **S07 [OC05] [TI03,TI04,TI06] Failures cannot render connection secrets**
  - **Given** a DSN with a distinctive high-entropy user, password, host, database name, query string, and certificate path, and each failure class – pre-dispatch exhaustion, unknown outcome, server error, pool exhaustion, version refusal, schema refusal
  - **When** the typed exception's `toString()`, `message`, and every public field are rendered, and the exception is logged through `package:logging` at severe with the exception as the error argument
  - **Then** none of the distinctive values, no raw driver message/detail/hint, and no nested driver exception text appears anywhere; the rendering carries only the operation class, the safe database identity (host, port, database name), a SQLSTATE where one exists, and actionable guidance

## Architecture Decision

**Approach**: `PostgresBackend` in `packages/dartclaw_core/lib/src/storage/` implements the S01 port over one `postgres` pool with a two-state dispatch classifier; `PostgresSchemaGate` reuses S02's `SchemaIdentity` with a backend-owned type mapping and catalog inspection; `DatabaseConfig` and the `StorageException` family live in `dartclaw_kernel`; the composition root selects the backend by config through S06's `DatabaseBackendFactory` seam. See ADR: `../dartclaw-public/dev/adrs/045-pluggable-database-backend.md` (decisions #7, #8; § Schema Bootstrap and Compatibility); topology: `../dartclaw-public/dev/adrs/056-package-topology-consolidation.md`.
**Why this over alternatives**: a separate `dartclaw_postgres` package breaks the saturated 12-package ceiling and the tier order has no exception mechanism, while `dartclaw_kernel` depends on nothing, so core is the only driver-bearing home; replay safety cannot be inferred from SQL text or API name, so the retry boundary is an explicit dispatch state rather than a heuristic; and fresh/current/refuse is the whole schema model because no PostgreSQL shape has ever shipped.


## Technical Overview

1. **`DatabaseConfig`** (`dartclaw_kernel`): `backend` (`DatabaseBackendKind.sqlite` | `.postgres`, default `sqlite`), `url` (`String?`, env-substituted at parse), `credential` (`String?`, a name, not resolved here), `poolSize` (YAML `pool_size`, default 5, positive). `const` defaults, `==`/`hashCode` like `SearchConfig`. `sqlite` keeps but ignores the other keys (a lingering inactive reference is legal, story S10); `postgres` requires exactly one of `url`/`credential` and a positive `pool_size`, otherwise a load warning naming the key. `database` joins the parser's known top-level keys, the composed section fields, `_sections` (`restart`), the field registry (four `FieldMeta`, `ConfigMutability.restart`, descriptions), and the core-key list (`database.backend`, `database.url`).
2. **Selection** (`database_backend_selection.dart`, core): `DatabaseBackendFactory databaseBackendFactoryFor(DatabaseConfig database, {required String Function(DatabaseConfig) resolveDsn})` returns `SqliteBackend.open` for `sqlite` and `(_) => PostgresBackend.open(dsn: resolveDsn(database), poolSize: database.poolSize)` for `postgres`; `Future<void> prepareAuthoritativeStore(DatabaseBackend backend, {required String storeName})` dispatches on the concrete backend to `SqliteSchemaGate.prepareTasks` or `PostgresSchemaGate.prepare`. Production sites use these when no factory is injected; tests keep injecting.
3. **DSN resolver seam** (`storage_wiring.dart`, exported for the CLI): `String resolveDatabaseDsn(DatabaseConfig)` – `url` returns the substituted value; `credential` throws `StorageConnectionException` before any connect, naming the reference and stating that named-credential resolution is not wired. Story S08 replaces the body; the signature is its seam.
4. **`PostgresBackend.open({required String dsn, required int poolSize})`** opens one pool, leases one connection to read `server_version_num` (< 140000 → `StorageConnectionException`, connection closed), and returns. `close()` closes the pool and is idempotent; later operations throw `StateError`. Startup failures take the same bounded pre-dispatch retry as any acquisition, then fail closed into wiring's existing fatal path.
5. **Seam operations**: portable SQL is rewritten to `$n` by S01's rewriter; rows marshal to the canonical scalar set (`bigint` → `int`, `double precision` → `double`, `text` → `String`, `bytea` → `Uint8List`; driver `bool`/`DateTime` from catalog paths normalized to `0/1` / ISO8601 text); `execute` resolves to affected rows. An owner `DatabaseStatement` is a reusable rewritten-SQL handle executed through the pool (physical preparation is per connection); a `tx`-prepared statement is bound to the leased connection and expires with the body.
6. **`transaction()`** leases one connection for `BEGIN … COMMIT`/`ROLLBACK` around the awaited body (TI01 settles `runTx` versus explicit statements), returns the body's value, rethrows after rollback. A `Zone` value carries the active context exactly as S01 #3: `tx` operations and zone-matched owner operations (including owner-prepared statements used inside the body) run on the leased connection; nested `transaction()` on `tx` or the owner throws `NestedTransactionError`; foreign-context operations lease other connections and never wait. This corrects the prior FIS wording that in-body owner calls "reject" – S05's repositories hold owner references and must join.
7. **Dispatch policy** (`postgres_dispatch_policy.dart`): two states, `preDispatch` and `dispatched`. Acquisition, open, authentication, and handshake failures before the operation's bytes are sent may retry to a fixed attempt bound with a short fixed backoff (private constants, no config surface); pool acquisition waits at most a fixed 30-second ceiling then throws `StoragePoolExhaustedException`. Calling the driver's execute/query or sending `COMMIT` crosses the boundary: transport loss thereafter is `StorageUnknownOutcomeException`, never replayed; an explicit server error response maps to `StorageQueryException` with its SQLSTATE. If the driver cannot prove pre-dispatch, it is dispatched.

10. **Schema** (`PostgresSchemaGate.prepare(backend)`): classify **empty** (no DartClaw-required relation in the default schema), **current** (marker row `(1, 1)` and every required object matching), or **incompatible** (everything else). Fresh bootstrap runs in one `transaction()`: every S02 tasks table and index, the base `memory_chunks` table (11 columns, no FTS object), and the marker. Type mapping: `TEXT` → `text`, `INTEGER` → `bigint`, `REAL` → `double precision`, `BLOB` → `bytea`; SQLite `INTEGER PRIMARY KEY` rowid aliases become `bigint GENERATED BY DEFAULT AS IDENTITY`, which the catalog check treats as that column's default. ## Constraints & Gotchas

- **Critical**: treat every SQL operation as potentially mutating – `query()` with `RETURNING` mutates; never classify retry safety by API name or SQL text. The only retry-safe class is a failure the driver proves happened before the operation's bytes left the process.
- **Critical**: no raw `postgres` exception, message, detail, hint, or DSN may be stored on a typed exception, rendered by `toString()`, or passed as a logger error argument; messages come from allow-listed safe fields only (Technical Overview #8). Secrecy tests use distinctive high-entropy fixture values, never `dartclaw`-like substrings.
- **Critical**: schema validation runs on the very backend instance later handed to repositories, before any repository is constructed – in wiring, `workflow status --standalone`, and `cleanup` alike.
- **Critical**: reentrancy follows S01 #3 exactly – zone-matched owner operations join the leased connection, foreign-context operations lease other connections. Routing an in-body owner write elsewhere breaks S05's atomicity; routing a concurrent write onto the leased connection interleaves it into the transaction.
- **Constraint**: one pool per `PostgresBackend`, one `PostgresBackend` per process; the transitional in-memory search store never touches disk. Story S10's interlock connection is separate from the pool by its own design.
- **Constraint**: the config gates are text scanners with fixed anchors – `final DatabaseConfig database;` between the `// --- Composed section fields ---` and `// --- Derived path getters ---` markers; a `_sections` line matching `'database': (tier: ConfigReloadTier.restart, …)`; a non-empty `description` per `FieldMeta`; kernel `*_config.dart` files never count as consumers, so each leaf's consumer lives in core or runtime (`backend` in selection, `url`/`credential` in `resolveDatabaseDsn`, `poolSize` in `PostgresBackend.open`). `DartclawConfig.load` stays confined to `loadDartclawConfig`.
- **Constraint**: LOC gates. Measured 2026-09-02: `dartclaw_core` 26269 of 27740; after S01–S06 this story's ~1200–1500 core lines are expected to cross the ceiling. The protocol is one raise in `arch_check.dart#_libLocCeilings` to measured plus at most `_locHeadroom` (1500) with a CHANGELOG `### Changed` note in the same change – never a silent bump, never a second package. No lib file over 1500 (split across the three backend files), no test file over 1300, no public constructor over 12 parameters.
- **Constraint**: barrel hygiene – every new `export` carries a `show`; every new public name is workspace-unique; `SchemaIncompatibleException` leaves the core barrel in the same change it enters the kernel barrel (`no_second_implementation`).
- **Constraint**: run `dart pub get` at the workspace root after adding the dependency; `dart test` runs suites as isolates in one process – live suites isolate per test through the support helper's namespace and never touch `Directory.current`.
- **Gotcha**: `workflow_run_migrations` is workflow domain data (S02 SC04): required on PostgreSQL too, rows never read by the gate.
