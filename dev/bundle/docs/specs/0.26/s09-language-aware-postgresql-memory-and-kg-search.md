## Feature Overview and Goal

**Intent**: A PostgreSQL deployment has no persistent memory search and no morphology-aware fact search, so a Swedish user cannot find `springer` by typing `springa` in either layer – this story gives the PostgreSQL backend the memory `FullTextIndex` and the direct KG fact search that core `tsvector`/`tsquery` already provides, under one configured language, without touching what SQLite stores, ranks, or prints.

**Expected Outcomes**:

- [OC01] On `database.backend: postgres`, memory search, recency listing, incremental projection, and `dartclaw rebuild-index` run against a persistent language-aware `PostgresFtsIndex` that honours story S03's port contract and `userId` isolation, and no SQLite store, file, or in-memory fallback is touched.
- [OC02] With `fts_language: swedish`, the query `springa` returns memory documents and, separately, authoritative KG facts containing `springer` or `springande`; `sprang` is returned by neither layer and is outside the acceptance bar.
- [OC03] One validated deployment-level language drives both paths: an unknown or server-missing name refuses serve and `rebuild-index` before any search object exists, naming the key, the value, and the server's valid configurations; after a change, KG search uses the new language on the first query after restart while stored memory vectors keep the old language until `dartclaw rebuild-index`.
- [OC04] KG facts stay authoritative in `kg_facts` with no stored vector or index and are never copied into a `FullTextIndex`; a PostgreSQL rebuild publishes by one transaction so a failure leaves the previous rows searchable; the SQLite default keeps its FTS5 memory search, substring KG matching, sibling-file rebuild, and printed output byte-for-byte; no task search exists.

## Acceptance Scenarios

- **S01 [OC01] [TI04,TI07] [runtime] PostgreSQL memory search honours the port contract with tenant isolation**
  - **Given** a prepared PostgreSQL database (S07 gate plus this story's vector column and GIN index), `fts_language: english`, and documents for `owner` and `other` sharing id `shared-id` whose chunks contain `secret`, with distinct text and metadata
  - **When** `PostgresFtsIndex` runs `search('secret')`, `listRecent`, `fetch(['shared-id'])`, `count` (with and without `{'role': 'topic'}`), `upsert` with `retire`, `delete(['shared-id'])`, `delete(['missing'])`, `replaceAll([])`, and an upsert whose second document has an empty chunk list, each with `userId: 'owner'`
  - **Then** every read returns only owner's documents (count `1` for the shared id) with metadata echoed verbatim and the stored UTC timestamp; `search` scores are positive `ts_rank` values ordered best-first; `listRecent` is `created_at DESC` then most-recently-stored first with score `0`; `fetch` returns chunks in stored order; after each mutation other's `shared-id` is unchanged and searchable; deleting a missing id is a no-op; `replaceAll([])` empties owner's corpus only; the rejected upsert throws `ArgumentError` and writes nothing

- **S02 [OC02,OC04] [TI04,TI05] [runtime] Swedish regular inflections match independently in memory and KG**
  - **Given** `fts_language: swedish`, memory documents whose chunks contain `hunden springer snabbt`, `springande barn`, `hunden sprang hem`, and `katten sover`, and four authoritative KG facts whose `value` fields carry the same four texts
  - **When** `PostgresFtsIndex.search('springa', userId: 'owner')` and `TemporalKnowledgeGraphService.allFacts(search: 'springa')` run
  - **Then** memory search returns exactly the `springer` and `springande` documents; KG search returns exactly the ids of the `springer` and `springande` facts in `entity ASC, valid_from ASC, id ASC` order as `KnowledgeFact` values, never as search documents; neither layer returns the `sprang` or `sover` records

- **S03 [OC03] [TI02,TI07,TI08] [runtime] An unknown or server-missing language refuses before any search object exists**

## Architecture Decision

**Approach**: Implement story S03's port a second time as a table-parameterized `PostgresFtsIndex` over S07's `PostgresBackend`, storing an app-populated `content_tsv` vector under a language-neutral GIN index; give `TemporalKnowledgeGraphService` a small fact-search dialect seam whose PostgreSQL strategy composes a query-time vector; move the reconciler's publication mechanics behind a target seam so PostgreSQL publishes by committing one transaction while SQLite keeps its sibling-file swap; bind the validated `fts_language` as `?::regconfig` data in every expression. See ADR: `../dartclaw-public/dev/adrs/045-pluggable-database-backend.md` (§ FTS Abstraction, § Configuration, open question 1).
**Why this over alternatives**: a generated `tsvector` column would bake the language into DDL and turn a language change into a schema change; a stored KG vector would add a projection FR5 explicitly defers; a staging-table swap on PostgreSQL would reimplement what a transaction already gives; dispatching on the backend class inside the KG service would tie an authoritative repository to driver types, while a two-strategy seam keeps the SQLite predicate byte-identical.


## Technical Overview

1. **Config** (`DatabaseConfig.ftsLanguage`, YAML `fts_language`, JSON `ftsLanguage`): default `english`; trimmed and lowercased at parse; blank refused with a load warning naming the key; carried but never validated under `sqlite`. Registry: `ConfigFieldType.string_`, `ConfigMutability.restart`, a description naming PostgreSQL configuration names and the `rebuild-index` consequence. Consumers: `StorageWiring.wire()` and `RebuildIndexCommand`. `ConfigSerializer.toJson` adds `ftsLanguage`.
2. **Validation** (`validatePostgresFtsLanguage(DatabaseBackend backend, String language)`, core): `SELECT EXISTS (SELECT 1 FROM pg_catalog.pg_ts_config WHERE cfgname = ?)` decides validity; `SELECT cfgname FROM pg_ts_config ORDER BY cfgname` supplies the list; failure throws `StorageConfigurationException(key: 'database.fts_language', value:, validValues:)`, a kernel `StorageException` subclass composed from those safe fields plus guidance. Called once per process before any `PostgresFtsIndex` or `PostgresFactSearch` exists: in the `postgres` branch of `wire()` and in `rebuild-index`, right after `prepareAuthoritativeStore`.
3. **Schema** (`PostgresSchemaGate`): the required manifest for `memory_chunks` gains `content_tsv tsvector NOT NULL` and the GIN index `memory_chunks_content_tsv_idx ON memory_chunks USING gin (content_tsv)`; fresh bootstrap creates both inside S07's transaction; validation compares them like every other object; the epoch stays `1` (no PostgreSQL shape has shipped). `NOT NULL` makes a skipped vector write fail loudly. The DDL names no language.
4. **`PostgresFtsIndex(backend, {required PostgresFtsTable table, required String language})`** and **`.withinTransaction(tx, {table, language})`** mirror `SqliteFtsIndex`; `PostgresFtsTable.memoryChunks` maps the SQLite descriptor's columns plus `contentTsv`. Writes insert one row per chunk with `content_tsv = to_tsvector(?::regconfig, ?)`; `search` is `WHERE user_id = ? AND content_tsv @@ websearch_to_tsquery(?::regconfig, ?) ORDER BY ts_rank(content_tsv, websearch_to_tsquery(?::regconfig, ?)) DESC, created_at DESC, id DESC LIMIT ?` with `ts_rank` as the score (positive, higher is better); `listRecent` is `created_at DESC, id DESC` with score `0`; the other operations follow S03 #2–#3 verbatim; every mutation validates first and runs inside `backend.transaction()`, the `withinTransaction` form relying on the enclosing one. `verifyIntegrity()` throws when the catalog lacks the vector column or the GIN index. The natural-language text is bound verbatim to `websearch_to_tsquery`, which never raises; a query with no lexemes matches nothing.
5. **KG dialect** (`knowledge_fact_search.dart`): `abstract interface class KnowledgeFactSearch { ({String sql, List<Object?> args})? predicate(String search); }`. `SubstringFactSearch` reproduces today's `_searchTerms` and per-term `instr(lower(…)) > 0` joined by `AND` (`null` for a blank search). `PostgresFactSearch(language)` returns one predicate `to_tsvector(?::regconfig, entity || ' ' || predicate || ' ' || value || ' ' || source) @@ websearch_to_tsquery(?::regconfig, ?)` with the raw text bound. `TemporalKnowledgeGraphService(backend, {KnowledgeFactSearch factSearch = const SubstringFactSearch()})` splices the predicate where the term predicates sit today; everything else is untouched. ## Constraints & Gotchas

- **Critical**: the language is data. Never interpolate `fts_language` into SQL or DDL; every expression binds it as `?::regconfig`; validity comes from `pg_ts_config`. A generated column or index expression naming a configuration would bake the language into the schema and break the `rebuild-index` contract.
- **Critical**: validate once per process, before any search object; an index or fact search built on an unvalidated name fails on first use with a raw cast error instead of the FR5 message.
- **Critical**: zero SQLite under `postgres`. The degraded posture keeps the persistent PostgreSQL index and records degraded health; `openSearchDbInMemory`, `SqliteBackend.openInMemory`, and `SqliteFtsIndex` must not appear on the `postgres` branch (story S10's probe fails otherwise).
- **Critical**: the transactional target holds one leased connection for the whole rebuild inside `transaction()`; every index write inside it goes through the `withinTransaction` index – a nested `transaction()` rejects with `NestedTransactionError` (S01 #3). Never await unrelated work inside the body.
- **Constraint**: KG results stay `KnowledgeFact` values in the service's own order; `ts_rank` is never applied to the KG path.
- **Constraint**: documented divergences, never asserted as parity (story S11's whitelist owns them): PostgreSQL stems and drops stopwords where SQLite matches quoted terms or substrings; an all-stopword query is empty on PostgreSQL and may match on SQLite; FTS5 `unicode61` folds diacritics (`hälsa` matches `halsa`) while the PostgreSQL `swedish` configuration does not; `websearch_to_tsquery` treats `-word` as negation and quotes as phrases.
- **Constraint**: Swedish fixtures assert exact id sets, never `isNot(contains('sprang'))` alone. Config gates are text scanners – the consumer reads `config.database.ftsLanguage` in `storage_wiring.dart` or `rebuild_index_command.dart` (never a kernel `*_config.dart`); regenerate the schema and reference with the S07 commands.
- **Constraint**: LOC gates. Roughly 600–800 core lib lines land after S07's raise; a crossed `dartclaw_core` ceiling takes the recorded-rebaseline protocol (`dev/tools/arch_check.dart#_libLocCeilings` plus a CHANGELOG `### Changed` note in the same change). No lib file over 1500 lines, no test file over 1300, no public constructor over 12 parameters.
- **Constraint**: comments are rationale-only; no story IDs in code, dartdoc, CHANGELOG, or user-facing text. `rebuild-index` documents "stop DartClaw first" and story S10 sanctions it as a one-shot concurrent client; this story adds no interlock and relies on the transaction for consistency.
