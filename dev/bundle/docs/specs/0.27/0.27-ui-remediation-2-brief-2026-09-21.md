# 0.27 UI remediation 2 – brief

**Written:** 2026-09-21 08:55 CEST. **Base:** `feat/0.27` at `425e29de`. **Predecessor:** `0.27-ui-remediation-brief-2026-09-19.md` and its handoff (`…-handoff-2026-09-20.md`). **Reproduction:** plain profile (`bash dev/testing/profiles/plain/run.sh`), Chromium at 800×600, owner screenshots of 2026-09-21.

## Findings (owner report, reproduced unless noted)

- **F1 Composer send group and queue rows.** `Queue` is a 24px `btn-sm`, its split caret an 18px `btn-sm` with a border, the send/stop button 28px: three heights in one row. Queue-row edit/remove are `btn btn-icon-sm`; `.btn-icon-sm` has no icon-only treatment of its own (only `.btn-icon` rests borderless and centres the glyph), so they render as bordered squares with the `[data-icon]::before` right margin pushing the glyph off-centre.
- **F2 Cryptic project name.** The chip and the popover show the implicit `_local` project, named after `Directory.current` (`project_service_impl.dart` `_createLocalProject`). `run.sh` `cd`s into a `mktemp -d` data dir, so the name is `dartclaw-plain-Zg27x0` and the directory `/private/var/folders/…`. Runtime behaviour is right; the profile's cwd is the defect.
- **F3 One popover for two controls.** Chip and model pill both open "Effective context": project + directory, provider, model, effort, plus Workspace / Current turn / Measurement / Behavior / Memory diagnostics. Model and effort are free-text inputs. The popover's controls are transparent until hovered (`.pop-context input.meta-val`), which reads as text, not controls.
- **F4 Commands button.** `data-icon="terminal"` (`>_`) is the same glyph as the sidebar's Agent entry. Clicking inserts `/` and opens the slash palette; in this profile the palette holds one row, so the effect is easy to miss. Owner reports "does nothing".
- **F5 "Request failed" on send – not reproduced.** Two sends (seed session, and a fresh New-chat session) both returned `200` from `/api/sessions/<id>/send` and completed turns. The toast comes from the sole `htmx:responseError` handler, so a non-2xx from an `hx-*` request is needed. No story; owner to capture the server log line (`HTTP: … [4xx|5xx] …`) from a failing attempt.
- **F6 Sidebar select mode.** The row checkbox (`.row-check`, 24×16 cell, 16px `form-checkbox`) sits at the row's top-left beside a 14px identicon line and, per the owner, cannot be clicked. Entry point reported as "clicking a project in the left bar"; the only coded entry is the view-options menu item **Select conversations**.
- **F7 404 button.** `.empty-state .icon` (hero glyph rule: `--text-2xl`, accent colour, glow) also matches the masked `icon-arrow-left` inside the `.btn-primary`: accent-on-accent makes it invisible and its 24px box shifts the label right.
- **F8 Settings tier badge.** Every field label carries an uppercase pill (`mode-badge`, `restart-badge`, `live-badge`); on the Agent tab that is nine `RESTART` pills in one card.
- **F9 Form controls.** Resting boundaries of `input.form-input` / `select.form-select` are near-invisible in dark; the opened option list is browser-native; the `custom-select` enhancer (`shared.js`, `app.css`) exists but is opt-in (`data-enhance`, four selects on Tasks) and carries a second dropdown vocabulary next to `.pop` + `.palette-item`.

## Decisions

- **D1** `run.sh`: the data dir becomes a fixed-name child of the temp parent (`<mktemp>/dartclaw-plain`); the trap removes the parent. The `_local` project then reads `dartclaw-plain`. No runtime change; whether the profile should `cd` into its data dir at all is noted, not changed.
- **D2** Two popovers, one apply path. **Project** (chip): Project select, Directory input, **Apply to next turn**, and a footer link to Session info. **Model** (pill): Provider, Model, Effort selects, the continuity banner, **Apply to next turn**. Workspace / Measurement / Behavior / Memory / Current turn leave the composer – Session info already lists them (`session_info.html:34-44`). One `applyContext` builds the payload from both forms' current controls (both are always in the DOM). Trigger ids `effective-context-open` and `effective-context-composer-provider` and the field ids stay, so the `/model` and `/effort` palette routes keep working after being pointed at the pill.
- **D3** `EffectiveContextCapabilities` gains `models` and `efforts` (`List<String>`, empty when the flag is false), declared by each harness – the provider adapter is the one authority for what it accepts. Claude: efforts `low, medium, high, max` (`control-protocol.md:128`); models are the CLI aliases `sonnet, opus, haiku` (`config_parser.dart` alias set, minus `default`/`opusplan`). Codex: efforts and models are whatever the repo already documents for Codex; where it documents none, the list stays empty. The Model select renders **Provider default** (`""`), the catalogue, and – when the staged value is outside it – that value as its own option, so a YAML- or API-set id stays representable. The Effort select renders **Provider default** plus the list. No new server-side validation: the harness passes the value verbatim and the turn fails if the CLI rejects it, as today.
- **D4** Keep the commands button; glyph becomes Lucide `square-slash` (new icon token), label "Slash commands (/)". Verify the palette opens from a fresh page with an empty, unfocused composer; fix any path where it does not.
- **D5** No change (F5 not reproduced).
- **D6** Select-mode checkbox: 14px control centred on the line-1 identicon row inside a 24px cell, the whole cell clickable, verified with a real click (checkbox toggles, bulk bar count follows). Reproduce the owner's entry point by clicking a row's project label and the scope button; if either enters select mode, that is a defect to fix. Escape exits.
- **D7** Scope the hero rule to the direct child: `.empty-state > .icon`. Check every `emptyState` fragment use keeps its glyph as a direct child.
- **D8** Mutability tier marker replaces the pill: `.field-tier` – lowercase, `--text-xs`, `--fg-overlay`, no fill, no border, no tracking, right end of the label row, `title` explaining the tier ("Applies after a server restart" / "Applies on config reload" / "Read-only here; edit dartclaw.yaml"). `live` renders no marker. The transient post-save states keep the same quiet text form in `--warning` ("restart required") and `--success` ("applied"). `.restart-badge` / `.live-badge` / `.mode-badge` stop being used on field labels; `.mode-badge` stays for its two remaining uses in `settings.html`.
- **D9** Form controls: (a) a per-theme `--border-control` token for `input.form-input`, `select.form-select`, `textarea.form-textarea` that clears 3:1 against card and page ground in both themes – ratios recorded in `DESIGN.md`; height stays at the 28px density tier; horizontal padding `sp-3` for text controls; focus ring unchanged. (b) The `custom-select` enhancer becomes canonical: every `select.form-select` is enhanced on load and after every HTMX swap (no opt-in attribute; `data-enhance` is removed from the Tasks templates). Trigger is visually the closed control (same box, border, inset, chevron token and divider). The menu is a `.pop` card of `.palette-item` rows with `.menu-tick` on the selected option (`role="listbox"` / `option`), max-height 18rem, keyboard ArrowUp/Down, Home/End, Enter/Space, Escape, first-letter type-ahead; closes on outside pointerdown and when focus leaves. The bespoke `.custom-select-menu` / `-option` / `-check` rules are deleted; the remaining custom-select CSS moves from `app.css` into `components.css` § Forms. `DESIGN.md` § Native selects becomes § Selects; `showcase.html` shows the anatomy. Touch tier: the trigger floors at 44px with the other controls.
- **D10** Send group at one tier: Queue and caret are joined as one 28px split button (Queue squares its right corners, the caret its left, shared border, no gap, caret 24px wide with a centred 14px chevron); the send/stop button stays 28px with `sp-1` before it. `.btn-icon-sm` gets the same icon-only treatment as `.btn-icon` (borderless rest, centred glyph, 14px) in canon. `.composer-recovery` gets a rule (the handoff's flagged gap): a quiet warning strip on the `.request-strip` pattern.

## Status (2026-09-21, after integration)

All three stories, their review fixes, the integration pass and the two runtime fixes (I2, I3) are on `feat/0.27` after `425e29de`; each landed after its own review. The final gate at HEAD is recorded below this section. Walkthrough captures: `.agent_temp/ui-remediation-2/final/` (integrated tree), `s-a/`, `s-b/` (per story).

Corrections to the findings above, established during implementation:

- **F4** – the palette was not a filter defect. `openCommands` prefixed `/` onto whatever the composer held, so a draft became a query that matched nothing and was altered in the same move; an empty composer always opened the full catalogue. A draft now opens the unfiltered palette untouched.
- **F6** – the checkbox was not unclickable; the view-options menu item carried `data-inbox-select-mode`, the same attribute the list uses as its state, so every click inside the list toggled the mode (a project label entered it, the checkbox left it). The command hook is now `data-inbox-select-toggle`.
- **F5 reproduced** as integration defect **I2** and fixed (`84bcd388`): `ClaudeCodeHarness._stopInternal` tore the process down without settling `_turnCompleter`, and the exit watcher returns early for an intentional stop, so the cancel-restart path awaited a future nothing completed; `executeTurn` never released its lease or the session lock, every later `send` hung, and the browser's abort surfaced "Request failed" with no server line. The 300s "stalled turn" warning was a consequence. **I3**: any crash or restart mid-turn leaves the session's dispatch claim `uncertain`, and `uncertain` gated admission and release for ever – release answered `409 DISPATCH_UNCERTAIN`, stop `404`, cancel made it worse by persisting `stopping` before a cancel that throws. **D11 (2026-09-21):** `uncertain` is informational, never a gate (S03 SC07's "non-executing" reading wins over OC03's wording); it settles on the next admitted send or observed outcome, and `_stopLocked` persists `stopping` only after the cancel succeeds. Evidence under `.agent_temp/ui-remediation-2/triage/`.
- Claude efforts are `low, medium, high, xhigh, max` (installed CLI); `control-protocol.md` corrected.
- Integration defects fixed: the enhancer re-reads the Model/Effort selects after a provider change; Escape reached select mode again once the always-present select menus were excluded from the "popover open" test; the layout gate verifies `aria-controls` targets itself because axe drops `hidden` subtrees.

Follow-ups, not done:

- UI: the enhanced menu always opens downward (in a popover near the viewport bottom it covers the fields below the control); `input.form-checkbox` / `.form-radio` keep the older 15% accent border; the slash palette stays open behind the model popover after `/model`; `.audit-row-toggle-spacer` carries a stale `.btn-icon-sm` size comment.
- Runtime, found during I3: `releaseNext` picks a held item whose commit state is integrity-failed, persists it `accepted`, and `_dispatch` then throws (HTTP 500, claim stuck); restart recovery closes approval records but never a `running` tool record, so a killed turn's tool card reads Running for ever; integrity-failure detail stores `'$error'` ("Instance of 'ConversationMutationException'") instead of the message; the stall watchdog is not disarmed on cancel and logs a misleading "Cancelling stalled turn" five minutes after an operator cancel; `conversation_service.dart` sits at the 1500-line fitness ceiling.
- Private repo: `deviations.md` rows 39–41 and this brief are copied into the `dartclaw-private` working tree, not committed there.
