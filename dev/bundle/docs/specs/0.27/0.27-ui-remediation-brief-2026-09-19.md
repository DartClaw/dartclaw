**Prepared:** 2026-09-19 11:54 CEST. **Status (2026-09-19 evening):** Phases 1–4 implemented in the working tree, uncommitted; independent review findings fixed; owner walkthrough pending. Open: FR9 container conformance run, Q/W gate receipts, real-device check.

## Diagnosis

1. **Backend is real; keep it.** FR1–FR8 are delivered, route-reachable and covered by invariant-level contract tests that survive a UI rewrite (`prd-outcome-audit.md` §1). FR9 is code-complete but its conformance row was never executed. FR10 is missing: no Q/W gate has a receipt, five recorded browser journeys failed with no superseding pass, `arch_check` fails today (runtime +5,434 LOC, core +1,933 over ceiling).
2. **Design system is intact.** 0.27 changed 8 lines of `components.css`. The damage is in 0.27's templates, `app.css` additions (+195 lines) and JS-built HTML.
3. **Mechanisms of the visual regression:**
   - `min-height: 44px` applied at all widths in eight `app.css` rules. PRD E11 asks 44×44 for essential *touch* actions; canon already has a ≤768px touch tier (`components.css:1003`).
   - Every new capability rendered as an always-visible bordered text button (`Attach`, `Context`, `New temporary chat`, `Export`, `Find in conversation`, `Settle selected`, `Next attention`, `Clear filter`, `Copy`, `Edit and continue`, `Fork from here`, `Retry`). Canon components that exist for the job were skipped: `btn-icon`, `.composer-model`, `.status-badge`, `.chip` filters, `.list-toolbar`, `.bulk-bar`, `.notif-*`, `.palette-item`, dialog header/body/footer.
   - Send lost `btn-icon` + `arrow-up`; `.composer-send` widened 32→44px in canon to fit the text label.
   - Effective-context card is a flex sibling of the composer, so it sits left of it.
   - Placeholder text leaks (`provider model · provider effort`); stray inbox count; double empty state; duplicated New Chat; context dialog renders its data twice; ⌘K input ~130px tall.
   - Functional regressions: tool calls stay `Running` after turn completion; `hx-history-elt` removed from chat main; Reset no longer re-renders; find reports N matches but reaches 20.
4. **Why no gate caught it:**
   - `dev/testing/profiles/conversation-loop/visual_comparison.sh:27` passes any screenshot within 20% pixel mismatch of the wireframe. On a dark UI that cannot fail.
   - S03 FIS line 392 deferred all browser/visual checks to the final gate; the final gate never produced a receipt.
   - The "refine wireframes first" tasks edited the bundle copies without rendering them. The refined `chat-conversation-cards.html` itself contains the 44px glue, the mis-placed context card and an empty `.tabs` strip. Canonical private wireframes are untouched since 2026-09-04. `deviations.md` has no 0.27 row.
5. **The PRD carries no visual-quality requirement.** Parity with Claude / Codex / T3 Code / OpenClaw 2.0 lives only in the research doc, which warns that feature presence alone will not deliver the experience. The existing five wireframes are also below that bar (sidebar filters consume ~40% of the rail before the first row, titles truncate at ~12 characters, the chat wireframe is a state dump). Implementing them faithfully would not reach the target.

## Remediation

Backend, routes, contract tests, controller logic and `data-*` hooks stay. The view layer is redone against a design target that is rendered and owner-approved before any template changes.

### Phase 1 – Design target (gate: owner approves screenshots)

One hi-fi HTML prototype on the real design system, `dev/bundle/docs/wireframes/chat-shell-target.html`, plus `chat-shell-target-density.css` holding proposed design-system corrections as overrides so they are reviewable before touching `components.css`.

Density tier (≥769px, fine pointer; touch tier ≤768px or `pointer: coarse` keeps 44px):

| Element | Now | Target |
|---|---|---|
| `.btn` | ~37px | 28px |
| `.btn-sm` | 28px | 24px |
| `.btn-icon` / `-sm` | 32 / 28px | 28 / 24px |
| `.form-input`, `.form-select` | ~37px | 28px |
| `.composer-send` | 44px | 28px icon |
| Topbar | 48px | 40px |
| Sidebar row | ~40px, two-line | 30px single-line; second line only for an attention reason |
| Chrome text | 14px | 13px (new `--text-sm`); message body stays 14px |
| Toolbar/icon buttons | bordered at rest | borderless at rest, fill on hover, focus ring kept |

Layout decisions:

- **Topbar:** title (inline rename) · context crumb (project identicon, provider · model) · state badge. Right: search icon with `⌘K` hint, attention bell, `⋯` overflow menu holding Session info, Find in conversation, Export, New temporary chat, Reset. No topbar New Chat at desktop; at ≤768px one icon button (PRD E6 requires new-chat outside the drawer).
- **Sidebar:** New chat row; one-row filter (All · Unread · Waiting *n* · more ▾ popover for Running/Done/Failed/Drafts/project); search collapses into the same row. Rows: identicon, title, trailing relative time or status dot; hover/focus reveals settle + archive icon buttons; checkbox only in select mode; `.bulk-bar` appears on selection; Settled is a collapsed tail. Waiting count is a small pill in the section header that jumps to next attention.
- **Transcript:** 760px column. Message actions are a 24px icon row revealed on hover/focus (always visible at touch tier) – copy, edit, fork, retry – with timestamp beside it. Tools collapse to one per-turn disclosure ("4 tools · 12s"); running/failed/blocked stay expanded.
- **Composer:** one container aligned to the transcript column. Row under the textarea: left `+` attach, `/` commands, context chip (project identicon + name → context popover); right model · effort pill, 28px send icon (`arrow-up`; `square` stop while running; `Queue` text variant while a turn runs, Steer in a split menu). Shortcut taught in the placeholder. Suggestion chips only in the empty state. Save status is muted 12px text that appears on change and persists only on failure. Queue/held items render as compact rows above the composer.
- **Context:** popover anchored to the chip, compact meta rows with inline edit; one representation of the data.
- **Temporary:** created from the overflow menu or New chat split; slim one-line banner.
- **Palette / find / attention:** canonical `.palette-item` rows with a 36px input and chip filters; find is a slim bar pinned to the top of the transcript with count and prev/next; attention panel uses canonical `.notif-*` rows.

States to render: empty/new chat, completed conversation with tools, running turn with queue + held item, pending approval with current-request strip, temporary chat, sidebar with 12 mixed-state rows + select mode, palette, find bar, context popover, attention panel – at 1440 and 390, dark and light.

### Owner decisions (2026-09-19)

Target approved after review rounds: `dev/bundle/docs/wireframes/chat-shell-target.html` (states `#s01`–`#s14`) supersedes the Phase 1 sketch above where they differ.
