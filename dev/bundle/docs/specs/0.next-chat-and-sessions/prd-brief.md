## Summary

Chat and session management are DartClaw's most-used surfaces and the core of the planned native app, yet today the sidebar shows title + badge only (web-delta B7) and chat still has silent-waiting gaps (B3). Competitors (T3 Code, Claude Code Desktop, Conductor) have made "many concurrent agent sessions, legibly" the defining control-plane experience. This milestone raises both surfaces to that bar on the Afterglow design system, guided by the T3 Code priority ladder: **observability → explainability → parallelism → reviewability → recoverability → drill-down on demand**.

Design principle: **latency is the brand** — instant session switching, no UI degradation under parallel sessions, server-first (Trellis + HTMX + SSE, zero-npm) throughout.

See the wireframe inventory + deviations #24.

File an amendment that **scopes Rule 1 to model-facing grammars**: the anti-pattern it bans is parsing model or user prose in Dart to reach a capability *the model cannot call*. A closed, explicit set of user-typed verbs in a UI, each bound to an existing HTTP endpoint, is a keyboard affordance over the API — not a prose parser over model output, and not a capability the model reaches by text. The MCP tools stay the model's path; the palette is the human's. Land the amendment before the catalog endpoint ships, so the rule and the code agree.

### Phase B – Session sidebar as control plane (inbox model)

Operator decision 2026-07-24: adopt the **full inbox model** from T3 Sidebar v2 (research §5) — the sidebar is a triage surface, not a recency-sorted list.

- **Settle/unsettle as a first-class server-side lifecycle**, distinct from archive (archive stays the deep-freeze: cancels turns, converts type). Settle is a light, reversible triage state: manual settle per row + bulk; auto-settle on task completion / N days idle (configurable); **auto-unsettle on any real activity** (incoming message, turn starting, needs-input) — defeasible triage is what makes it trustworthy. Settled sessions collapse to slim rows in a paginated tail; content stays readable without unsettling.
- **Flat, statically ordered active list** — activity never reorders rows; only settle/unsettle transitions move them. Project identity as metadata, not hierarchy: per-row project icon/favicon + name, with project **scope chips** as filters (replaces "group by project" as the primary mechanism; grouping may return later as an option).
- **Ambient status glyphs + attention damping** on session rows: running / waiting-on-you / done / failed, live over SSE, with elapsed timer on running rows (pairs with Afterglow identicons, which stay entity-only). Non-actionable running rows are visually damped; color (status-dot/edge-stripe vocabulary) is reserved for blocked-on-you and failed — the eye lands on what needs a decision.
- **Live-everywhere substrate**: session-list and chat-view updates push to *all* viewers — today a turn started by a channel message, cron, or another tab is invisible to a passive viewer until reload, and the Chats lane never updates live. This substrate underpins ambient status, auto-unsettle, and steer/queue, and closes the sidebar's unbounded-list gap (cap + paginate the settled tail).
- **OH-12** (moved): scope visibility, search, sidebar metadata, LLM-generated titles, incognito/temporary session, export.
- **"Waiting on you" as a first-class filter** alongside the status/project chips.
- **Drag-resizable sidebar width** (new, 2026-08-05): a drag handle on the sidebar/content edge adjusts `--sidebar-w` within min/max clamps, double-click resets to the canonical 260px default, and the chosen width persists per browser (client-side preference — no server storage). Canon impact: `--sidebar-w` becomes a user-adjustable default rather than a constant; DESIGN.md's "no collapsed-sidebar mode" stance is unchanged (the min clamp keeps labels readable — resize is not collapse). Keyboard-accessible per the Phase C layer (handle focusable, arrow keys nudge). Line item on an existing Phase B sidebar story, not a story of its own.
- Session lineage: parent/fork chain visible on forked sessions (fronts Session Lineage backlog item).
- **Wireframe rework required**: `session-sidebar-control-plane.html` (WIREFRAMED 2026-07-04) predates the inbox decision — project-grouped rows must become flat rows + project chips/icons, and settle affordances + settled tail must be added before planning. **Sequencing decided 2026-07-25: rework after 0.23's canon stories land** (surfaces, type scale, form/tab/dialog primitives), not before. Both this file and `chat-command-palette.html` hardcode tokens whose meaning 0.23 changes — including one the type-scale story deletes — so redrawing now means redrawing against a substrate that no longer exists, and the palette rework additionally wants the new `.dialog`/form primitives. There was no schedule cost, since planning was itself gated on 0.23. Productive exception: the **settle information architecture** (what a settled row shows, where the tail sits, what bulk-settle looks like) is independent of the token values. **Status 2026-08-07**: 0.23 canon landed and the `chat-command-palette.html` rework is done on it (see Phase A command surface); the `session-sidebar-control-plane.html` rework remains pending. **2026-09-03**: 0.23 shipped as `v0.23.0`, so the sidebar rework is unblocked and is now the one wireframe deliverable owed before planning.

## Success Criteria

Each criterion below is stated so it can fail. The PRD turns them into per-FR acceptance criteria; the *how it is proven* column is the part that must survive into the plan, because several need a test harness that does not exist yet (a multi-viewer SSE fixture, and a seeded N-session profile).

| # | Criterion | How it is proven |
|---|---|---|
| SC1 | No silent waiting: every turn shows a state within 500 ms of send — `.msg-thinking` before first token, streaming cursor during, terminal state after | Scripted send against the `visual` profile; assert a state element exists in each window |
| SC2 | Triage in one glance: with 10 concurrent sessions of mixed state, every session needing input is identifiable without scrolling or hovering, and reachable in one keystroke | Seeded profile + screenshot review; count colour-bearing rows (must equal the blocked/failed count, no others) |
| SC3 | Settle is defeasible: a settled session that receives a message, starts a turn, or needs input returns to the active list without user action | Integration test per trigger — three cases, not one |

| SC5 | Live everywhere: a turn started from a channel, a cron job, or a second tab is visible in a passive viewer's sidebar and chat without reload | Multi-viewer test, one case per origin (channel / cron / other tab) |
| SC6 | Session switch renders in ≤200 ms perceived (fragment swap); no visible jank with parallel running sessions | Timed fragment-swap measurement on the seeded profile |
| SC7 | One catalog, no drift: every session action is reachable via `/` and via Cmd+K, both sourced from the same endpoint; a `/`-command DartClaw does not own reaches the harness unchanged | Contract test over the catalog endpoint + a passthrough test per harness provider |
