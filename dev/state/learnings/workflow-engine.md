# Workflow Engine

- **Strict task-spawn dependencies need a lifecycle-only construction path.** `WorkflowService`'s default constructor requires task-persistence ports (production wiring fails at compile time when missing); tests that only exercise pause/resume/cancel/list should use the explicit lifecycle-only constructor, not fabricated persistence ports.
- **Shared worktree caches need both persisted bindings and per-key mutexes.** In-memory map alone fails on retry/restart; same-key fanout needs a `finally`-released waiter/completer guard.
- **Validator file splits must preserve diagnostic ordering.** `workflow validate` output order is observable; rule-group moves need either the original call sequence in the composer or golden coverage for ordering.
- **`git worktree list` automation must use `--porcelain`.** Human-format output is not stable for reconciliation.
- **Every `format: path` output resolves under one rule, and the worktree diff is not part of it.** `resolveFileSystemOutput` (0.25): an existing symlink-contained claim wins, probed against the roots in order — step artifacts dir, worktree, runtime-artifacts, project data; with no usable claim the value is captured from the step artifacts dir, selected by the output's own `pathPattern`/`preferPatterns`. The bare-suffix alias survives for the *path* key only (`_fileSystemClaimKey`), not for counts. Engine-owned roots yield absolute values. Contract-locked in `built_in_workflow_contracts_test.dart` and `context_extractor_path_outputs_test.dart`.
- **Merge inside the integration worktree when the integration branch is checked out there.** Reusing the main checkout fails with `branch is already used by worktree` once a shared worktree owns the branch.
- **e2e artifact capture must snapshot the *terminal* task config**, not the queued snapshot. Otherwise completion-time writes are silently hidden even when the row was updated correctly.
- **Workflow agent steps should omit `type:` or use `type: agent`.** Removed authoring values (`custom`, `coding`, `research`, `analysis`, `writing`, `automation`) fail validation; read-only behavior belongs in `allowedTools`, not semantic step names.
- **Loop exit gates only see exact context keys — step outputs are NOT auto-namespaced.** A gate like `re-validate.findings_count == 0` requires the step to emit that dotted alias explicitly.
- **Broad `stepDefaults` glob patterns silently drift after step renames.** Re-validate the defaults layer whenever step IDs change.
- **Loop crash recovery needs a checkpoint after every successful sibling step.** Checkpointing only at iteration boundaries loses outputs the next sibling depends on.
- **Workflow start must preflight and persist effective `PROJECT`/`BRANCH` before any workflow task is created.** Deferring resolution to `TaskExecutor` lets invalid runs leak tasks and serves authored defaults to early prompts.
- **Resolve a null `gitStrategy` as the default `auto` before keying behavior on the mode.** All resolution flows through `step_config_policy.resolveWorktreeMode`, so a strategy-less parallel map/foreach resolves to `per-map-item`, and the concurrency clamp keys on the *resolved* mode (`'inline' ? 1 : maxParallel`) so clamp and dispatcher agree. The old `?? 'inline'` collapse made the dispatcher skip per-item worktrees while iterations ran concurrently against one shared checkout — fix at the resolution layer, never a clamp special-case.
- **A foreach dependency-hold pause has no resume path.** After a settled-failed story blocks a dependent, `workflow resume` re-pauses immediately (retry needs failed state; the frozen definition snapshot ignores YAML edits) — cancel and start a fresh run; discovery re-derives only unfinished stories.
- **Local-path projects need their dirty-tree / branch-mismatch gate at the same workflow-start seam.** Putting the check later leaks workflow tasks against a live checkout.
- **Workflow git cleanup must run after child-task shutdown and walk the full run-owned set.** Shared-key cleanup is insufficient for `per-map-item` workflows.
- **Artifact auto-commit must verify task worktree paths are real git worktrees.** Test scaffolds and workflow workspaces may materialize outputs in temp dirs; commit load-bearing artifacts to the resolved project checkout.
- **Artifact commit must use output resolver semantics, not raw output formats.** List-shaped filesystem outputs can be represented as `lines` yet still be load-bearing artifacts.
- **Dependency-aware fan-out is explicit, not inferred from object shape.** The shared map/foreach scheduler engages only when items declare `dependencies`; root records in that mode still need `dependencies: []`, or validation correctly treats the collection as malformed.
- **Resume `story_specs` prune deps by completion status, not absence.** `validateStorySpecsContract(completedStoryIds:)` drops a dep only when it names a `done`/`skipped` plan story; ids absent for other reasons (no `fis`, `blocked`, dropped) stay, so `DependencyGraph` still rejects typos and incomplete prereqs. Null catalog → strict.
- **Promotion-conflict retries need the iteration cursor preserved on failure.** Clearing `executionCursor` after a blocked promotion makes downstream items permanently undispatchable and breaks `workflow retry`'s ready-set.
- **Every task-completion listener shares the same async-listener / SQLite-teardown race.** Each needs the synchronous-listener pattern: filter `failed + retry-in-progress` and `queued|running` re-emissions, then fire-and-forget `_taskService.get` for terminal events. Fixing one dispatcher and not its siblings leaves the others ticking. (Historically `step_dispatcher` and the since-deleted `map_iteration_dispatcher`.)
- **A `mapOver` step without per-item steps is no longer executable.** The single-step map controller was deleted in 0.25: `foreach` is the only iteration controller, and declaring `map_over` without `foreach_steps` is a validation error (and a loud run failure for a run persisted before the removal). Tests must use `type: foreach` + `foreachSteps: [...]`.
- **Multi-flag idempotency persists are crash-windows.** Two booleans persisted in sequence reopen the work if a crash lands between them. Use a single atomically-persisted phase-string field (`enacting`/`drained`/`none`).
- **Per-attempt artifact filenames must scope by foreach iteration index.** `merge_resolve_attempt_<n>.json` collides across iterations under one task id; use `merge_resolve_iter_<i>_attempt_<n>.json`.
- **Bash variable interpolation must shell-escape both `{{context.X}}` and `{{VAR}}`.** Asymmetric escape-vs-raw is an injection footgun; the contract is "all interpolations escape — literal text is written directly in the template."
- **Schema validator strictness is signaling, not enforcement.** Treat `additionalProperties: false`, `enum`, `minimum`, `maximum` as warnings under the soft-validate contract — they catch preset drift without breaking legacy YAML.
- **`workflow_definition_parser._parseGitStrategy` is the real wiring gate for `gitStrategy:` extensions.** A new typed sub-block on `WorkflowGitStrategy` without parser threading is silently dropped from YAML-sourced workflows while validator unit tests stay green. Add parser threading + a parser test in the same change.
- **Workflow validators that compare provider roles need runtime role defaults.** Alias equality (`@executor` vs a concrete provider) is only meaningful after resolving through `WorkflowRoleDefaults`; CLI validation and server wiring must construct validators with the same configured defaults the runtime uses.
- **Use task-level `maxRetries` for harness crashes, not `onFailure: retry` for story steps.** `onFailure: retry` also retries explicit failed `<step-outcome>` results, re-entering a per-story worktree that contains the prior semantic failure's partial diff. Record failed slots and let review/summary steps consume the aggregate.
- **Standalone workflow teardown must preserve non-terminal workflow git state.** Approval-held, paused, and running workflows still need their integration branch and per-map worktrees for resume; reap only terminal runs on process dispose.
- **Best-effort cleanup steps use `onFailure: continue`, not a cleanup-specific branch.** Optional advisory steps (e.g. the council reviews) may emit `needsInput` on red baselines; `continue` covering both `failed` and `needsInput` keeps required producer/review semantics strict without special cases.
- **Post-step artifact validation must follow the producing task worktree.** Validating path outputs against a root resolved before git isolation bound the task worktree rejects files the step wrote. Prefer `task.worktreeJson.path`; active root only as the no-worktree fallback.
- **Live workflow step-isolation tests must cancel provider turns before deleting sessions.** Test timeouts can fire while a Codex subprocess is still returning; call the runner cancellation seam before disposing message storage or removing the temp session dir.
- **`gating_findings_count` counts findings at or above `defaultGatingSeverity` (`high`), not fix-character.** `defaultGatingSeverity` is the single threshold source (there is no per-step or `stepDefaults` override) and it reaches the model through the `schema_presets.dart` prompt fragment alone — since 0.25 there is no host-side derivation of a count, so the emitted integer is the count. Loop entry/exit measure only, never a terminal pass/fail gate — sub-threshold findings report but don't block, so loops converge.
- **When replacing a bespoke validator with a generic one, prove EVERY axis it enforced — containment, existence, AND argument-safety — at the generic surface, for every output shape.** ADR-041's decoupling silently dropped argument-safety on the spec workflow's bare `spec_path` while all tests stayed green (only the `story_specs` shape was exercised). Fix: `context_extractor._assertArgumentSafeFileSystemOutput`. See also Package Architecture § green tests can mask unwired features.
- **Un-gating onto a generic validator means removing EVERY fail-closed layer keyed on the same precondition, not just the dispatch gate.** Two stale "no active workspace root" guards (run-level pre-dispatch + a post-validation override) shadowed the generic path's correct no-root behavior while its unit tests stayed green. Grep all guards on the precondition; fix replaced `_requiresActiveWorkspaceRoot` with `_emitsStorySpecs`.
- **A canonical manifest holds only if BOTH write and read sides honor it.** `SkillProvisioner` wrote the DC-native skill cache from the manifest, but inventory discovery read it back by wildcard, so stale skills leaked past manifest removals. Fix: write-side purge of unmanifested `dartclaw-*` cache dirs + read-side intersection against the persisted manifest (`dc_native_skill_manifest.dart`). When declaring a source of truth for an inventory, audit every reader — glob discovery silently reopens the drift.
