## Candidate identity

A working-tree result is valid only when one receipt binds all of these fields:

- `kind: working-tree`;
- the 40-character `head` from `git rev-parse HEAD`;
- the exact ordered scope `packages apps dev docs CHANGELOG.md pubspec.yaml pubspec.lock analysis_options.yaml`;
- SHA-256 of both staged and unstaged binary diffs; and
- every untracked in-scope input path and its SHA-256.

A clean release result instead uses `kind: committed`, an exact `head`, and `porcelainEmpty: true`, then reruns every
required gate on that SHA. A working-tree pass is never relabelled as committed evidence.

Capture the working-tree identity before a run:

```bash
mkdir -p .agent_temp/qualification/0.27/identity
git rev-parse HEAD >.agent_temp/qualification/0.27/identity/head.txt
git diff --cached --binary --no-ext-diff -- packages apps dev docs CHANGELOG.md pubspec.yaml pubspec.lock analysis_options.yaml >.agent_temp/qualification/0.27/identity/staged.patch
git diff --binary --no-ext-diff -- packages apps dev docs CHANGELOG.md pubspec.yaml pubspec.lock analysis_options.yaml >.agent_temp/qualification/0.27/identity/unstaged.patch
git ls-files --others --exclude-standard -- packages apps dev docs CHANGELOG.md pubspec.yaml pubspec.lock analysis_options.yaml >.agent_temp/qualification/0.27/identity/untracked.txt
shasum -a 256 .agent_temp/qualification/0.27/identity/staged.patch .agent_temp/qualification/0.27/identity/unstaged.patch >.agent_temp/qualification/0.27/identity/diff-sha256.txt
while IFS= read -r path; do shasum -a 256 "$path"; done <.agent_temp/qualification/0.27/identity/untracked.txt >.agent_temp/qualification/0.27/identity/untracked-sha256.txt
```

Every producer receipt records its gate, exact candidate, environment, invocation, timestamp, outcome, artifacts,
assertion IDs and direct receipt paths. Failed attempts remain in the ledger; a retry points to them rather than
overwriting them.
