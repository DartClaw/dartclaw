# Package Rules — `dartclaw_server`

**Role**: HTTP API + HTMX web UI + task runtime + container orchestration — the composition layer that wires `dartclaw_core` services behind shelf routers and Trellis-rendered pages. Entry points: `DartclawServer` (`lib/src/server.dart`), `ServerBuilder`, `TurnManager`, `TurnRunner`, `ExecutionCoordinator`, `TaskExecutor`, `TaskService`.

## Architecture
- **HTTP layer** — `DartclawServer` + `ServerBuilder` (composition root); shelf middleware (auth, security headers); `lib/src/api/*_routes.dart` (one router per domain); `sse_broadcast.dart` + `stream_handler.dart` for streaming.
- **Web UI** — `PageRegistry` (registration with reserved-prefix guard) + `lib/src/web/pages/`; Trellis templates under `lib/src/templates/` (paired `.html` + `.dart`, manifest in `expectedTemplates`); vendored static assets in `lib/src/static/`.
- **Turn orchestration** — `TurnManager` (routing, reservation, status/cancel ownership, `BusyTurnException`, provider-side continuity reset), `TurnRunner` (scoped prompt/persona resolution + harness drive + guard wiring + wait-state event emission), `turn_wait_status.dart` (server API/UI status model + `TurnCancelReason`; the `TurnWaitState`/`TurnWaitReason` enums now live in `dartclaw_core` and are re-exported here), `ExecutionCoordinator` (post-governance session admission, one serialized primary lane plus per-provider worker leases, lazy construction, reuse, and capacity snapshots), `TurnGovernanceEnforcer` (turn-level limits).
- **Task runtime** — `TaskService` (CRUD), `TaskExecutor` (queue consumer), `WorktreeManager`, `MergeExecutor` / `RemotePushService` / `PrCreator` (git ops; injected into `WorkflowGitPort`), `task_*_subscriber.dart` (`EventBus` side effects).
- **Container orchestration** — `ContainerManager`, `DockerValidator`, `SecurityProfile`, `BridgeBinaryProvisioner`, plus the host gateway under `lib/src/container/gateway/` (`HostGateway`, `GatewayPipe`, `ProviderAdapter`, `McpBridgeSurface`) — host-mediated provider and MCP access for `network:none` containers.
- **Workflow glue** — `lib/src/task/workflow_*.dart` injects `WorkflowGitPort` + `WorkflowTurnAdapter` impls into `dartclaw_workflow`; reads workflow runtime state from the hydrated `WorkflowStepExecution` row.
- **Channel wiring + MCP** — `webhook_routes.dart` (synchronous inbound + JWT verification; channel impls themselves live in their own packages); `lib/src/mcp/` (Dart-side MCP endpoint at `/mcp`). The endpoint requires the gateway bearer when auth is enabled; without auth it is mounted only on a configured loopback host, and the request Host must remain exact loopback. Web-search MCP tools share `search_mcp_tool.dart`'s `SearchMcpTool` base (schema/validation/clamp/ContentGuard scan/result formatting); `BraveSearchTool`/`TavilySearchTool` supply provider metadata to that base, each paired with its own `SearchProvider` (HTTP shape differs per API).
- **Security wiring** — `SecurityWiring` translates `GuardChain` verdicts to `EventBus` events (the seam `dartclaw_security` deliberately doesn't cross).

## Shape
- **Request lifecycle**: shelf pipeline (auth middleware → security headers → router) → `*_routes.dart` handler → one-shot response or SSE via `sse_broadcast.dart`.
- **Turn lifecycle**: route handler → `TurnManager.reserve(sessionKey)` (acquires session lock; returns turn token or `BusyTurnException`) → `TurnRunner.execute` (composes prompt, drives `AgentHarness`, applies guards, fires events) → outcome → lock released.
- **Task lifecycle** runs in parallel: `TaskExecutor` consumes the queue, manages worktrees + git ops, emits `TaskEvent`s — workflow-spawned tasks auto-accept, manual tasks park for review.
- **Container orchestration** wraps containerized harness execution: `ContainerManager` applies `SecurityProfile` and delivers the bridge binary read-only; `HostGateway` binds each `docker exec -i` pipe to one authority, one surface, one upstream, and one tool policy.

## Boundaries
- Allowed prod deps (arch_check L1): `dartclaw_bridge`, `dartclaw_config`, `dartclaw_core`, `dartclaw_google_chat`, `dartclaw_models`, `dartclaw_security`, `dartclaw_signal`, `dartclaw_storage`, `dartclaw_whatsapp`, `dartclaw_workflow`. Plus shelf, trellis, http, anthropic_sdk_dart, crypto/jwt/pointycastle, html2md, qr.
- This is the only package allowed to import from all channel packages and storage. Channel-specific transport stays in its own package; this package only wires it.
- Container orchestration (`lib/src/container/`) lives here, not in core — `ContainerManager`, `DockerValidator`, `SecurityProfile`, `HostGateway`. Don't move it down. The framed wire contract itself lives in `dartclaw_bridge`, which both this package and the in-container executable compile against; nothing security-relevant may move there, since the bridge runs inside the boundary.
- Workflow execution semantics belong in `dartclaw_workflow`. Workflow-task glue (`workflow_one_shot_runner.dart`, `workflow_turn_extractor.dart`, `workflow_worktree_binder.dart`, `workflow_cli_runner.dart`) lives under `lib/src/task/` and injects git impls (`MergeExecutor`, `RemotePushService`, `PrCreator`) into the workflow port. Ownership decision for `WorkflowCliRunner` recorded as 2026-05 addendum to ADR-023 (private repo `docs/adrs/023-workflow-task-boundary.md`).

## Conventions
- Add new dashboard pages by registering a `DashboardPage` with `PageRegistry` (`lib/src/web/page_registry.dart`). Routes must start with `/` and not collide with the reserved-route patterns (health, static, /login, channel pairing, etc.) — `register()` throws on conflict. Nested destinations that should remain routable without becoming top-level sidebar items implement `DashboardNavigationExclusion`; their handlers activate the parent destination when building nav items.
- Templates are paired `.html` + `.dart` files under `lib/src/templates/` (loaded by `loader.dart`; the file names are listed in `expectedTemplates` — startup fails if missing). Use Trellis with HTML-escaped placeholders; never concatenate user data into HTML strings. Follow `dev/guidelines/HTMX-GUIDELINES.md` and `dev/guidelines/TRELLIS-GUIDELINES.md` for fragments and SSE.
- Static assets under `lib/src/static/` are **all** vendored — see `VENDORS.md` (highlight.js, DOMPurify, htmx-ext-sse, Stimulus, htmx, marked, JetBrains Mono). There are no CDN exceptions: every subresource loads same-origin and the CSP names no external origin. Do not add npm/CDN runtime fetches — `dev/tools/fitness/check_no_external_origins.sh` fails the build on any external subresource in the templates, the served CSS, or the CSP.
- `lib/src/generated/embedded_assets.g.dart` is generated, **not committed** (gitignored). `lib/` imports it, so a fresh checkout does not analyze until you run `dart run dev/tools/embed_assets.dart`. Re-run it after any template or static asset edit; never hand-edit it. CI, `dev/tools/build.sh`, and `dev/tools/release_check.sh` generate it automatically.
- `AssetResolver` selects explicit/dev/source-tree files before the embedded fallback. Embedded templates load from the generated map; embedded static files use the in-memory handler. Keep filesystem serving for live-edit modes.
- Routes go under `lib/src/api/*_routes.dart` (one shelf router per domain) with helpers from `api_helpers.dart`. SSE streams use `sse_broadcast.dart` / `stream_handler.dart` — don't roll new SSE plumbing. `sseResponse` disables Shelf and proxy buffering by default; frame/header primitives in the same module provide UTF-8 framing, guarded sends, and the explicit buffering header variants. Reuse them instead of inlining `'data: …\n\n'` / response plumbing.
- Auth resolution and base-URL handling belong in middleware/`auth/`, never inline in routes. Use `AllowlistValidator` for outbound URL gating.
- Turn lifecycle: callers go through `TurnManager.reserve` → coordinator lease → `TurnRunner.execute` → outcome/release. `BusyTurnException` is the public busy signal. Don't construct `TurnRunner` directly in routes — go through `TurnManager`.
- Turn cancellation is accepted only while provider execution is active. Once the provider returns or throws, one settlement owner completes guards, persistence, daily logging, and compaction without exposing a cancellable state.
- A nonblank `systemPromptOverride` bypasses behavior and memory composition verbatim. Logical-agent sessions acquire an `ExecutionCoordinator` worker lease for the exact provider and effective execution policy; never fall back to the primary lane. All placement resolves through `ExecutionPolicyResolver` — no caller may infer placement from a nullable container manager or re-derive precedence locally. `sessions_spawn` creates the hidden conversation; `sessions_send` requires its existing handle and continues persisted history. Coordinator construction inputs are immutable, so healthy idle *host* workers may be reused only for the same provider and identical `ExecutionPolicy`, preferring the same session. Container workers are never cached: each live container authority owns a dedicated container, and release confirms termination, runs the release-hook seam, destroys the container, and only then returns capacity (ADR-012, 2026-08-11 amendment). A container authority also owns its bridge pipes: `SecurityWiring.acquireContainerAuthority` returns only once every required surface has handshaked and is listening, and release deregisters health monitoring, revokes the pipes, then destroys the container. Failed first turns use `resetProviderSessionContinuity` so cleanup skips the still-active primary MCP caller and clears idle workers only.
- Built-in prompt jobs may carry an internal `ScheduledJob.allowedTools` policy. `ScheduleService` forwards it unchanged; user YAML cannot set it.
- Session reset lifecycle: clear provider-side continuity through `TurnManager.resetSessionContinuity(sessionId)` before persisted messages/attachments are reset. If continuity reset reports busy, return the same `BusyTurnException`/409 path rather than clearing visible state first.
- Session send, title, lifecycle, and reusable-New-Chat decisions share the factory-owned `SessionMutationCoordinator`. Re-read mutable session eligibility inside its per-session critical section before acting; an earlier request snapshot is not authoritative.

## Gotchas
- **`ServerBuilder.taskToolFilterGuard` is host-supplied, never fabricated.** `buildTurns()`'s single-harness compatibility path (SDK hosts and tests) receives an already-constructed `worker`, so the builder cannot retrofit that harness's guard chain. The host must create the `TaskToolFilterGuard`, layer it over the base chain (`GuardChain.layered(base:, guards: [filter])`), hand *that* chain to the harness, and set the same instance on the builder — otherwise `startTurn(allowedTools:)` / `readOnly` are silently inert. Never re-introduce a builder-created filter. Coordinator-managed runners carry their own filters (see `dartclaw_cli` `wiring/harness_wiring.dart`).
- SQLite is bundled by default — no committed `hooks.user_defines.sqlite3.source: system` block. Release binaries build with `dart build cli` (`dev/tools/build.sh`), which emits a bundled `libsqlite3` from the sqlite3 hooks; committing a `source: system` block would make them depend on the host SQLite (Windows' `winsqlite3.dll` lacks FTS5). The only sanctioned escape hatch is an *uncommitted* `source: system` edit for macOS codesign-blocked local iteration — see `dev/guidelines/KEY_DEVELOPMENT_COMMANDS.md`.
- Workflow-spawned tasks have `reviewMode: auto-accept` (set by the workflow package); the server's review surface won't park them — assume they advance on `accepted`.
- Reserved route patterns in `page_registry.dart` are guarded — `/health`, `/static/`, `/whatsapp/`, `/signal/`, `/memory/content`, etc. Adding a page on a reserved prefix throws at startup, not at request time.
- `TaskExecutor` reads workflow runtime state from the hydrated `WorkflowStepExecution` row, not from `Task.configJson` — workflow-private blobs no longer round-trip through tasks.
- The `task_*_subscriber.dart` files attach to the `EventBus` — adding a new subscriber requires wiring it in `ServerBuilder` so it's actually subscribed.
- `dartclaw_server.dart` barrel is large but ceiling-checked (≤110 exports) — prefer adding sub-barrels (`*_exports.dart`) over piling onto the top barrel.
- The claude workflow one-shot provider (`task/claude_cli_provider.dart`) runs `claude -p --output-format stream-json --verbose --include-partial-messages` and parses the terminal `type: "result"` NDJSON event — **not** `--output-format json`. Streaming is required for stall-monitor liveness: `CliProcessSupervisor` resets the silence timer per stdout line, and buffered single-object output emits nothing until completion, false-tripping the stall guard on long turns. Authoritative token counts live under the result event's nested `usage` map (`usage.input_tokens`, `usage.cache_read_input_tokens`, `usage.cache_creation_input_tokens`), not top-level keys; `_parse` reads `usage.*` with a legacy top-level fallback. Live progress uses completed `assistant` events and emits `WorkflowCliTurnProgressEvent` with latest input/cache and summed output tokens.
- Full-access claude one-shot spawns (`approval: never`) override `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=0` in the spawn env (`_fullAccessEnvOverride`, merged last in `ClaudeCliProvider.run`). The provider env sets the v0.14.6 hardening `=1` on every claude spawn, but the current claude CLI treats that as a signal to force `--permission-mode default`, silently neutralizing the bypass posture full access needs (`bypassPermissions`/`--dangerously-skip-permissions`). Policy-enforced steps keep `=1` — `--settings permissions.allow` rules are honored under `default`. Decision in `dev/state/DECISIONS.md` (Still Current, 2026-07-07); don't re-apply the scrub uniformly.

## Testing
- Test layout mirrors `lib/src/` — domain-keyed subdirs (`api/`, `task/`, `templates/`, `container/`, `harness/`, `governance/`, `mcp/`). Layer 3 handler tests invoke shelf handlers directly via `handler(Request(...))` — no TCP bind.
- API route tests should use `test/api/api_test_helpers.dart::ApiRouteTestClient` for routine handler calls, status assertions, and JSON decoding. Keep tests phrased around route contracts: method, path, expected status, response body, headers, and side effects. Reach for raw `Request` only when the test needs unusual headers, malformed bodies, streaming, or another non-standard request shape.
- Use shared fakes from `dartclaw_testing` (dev_dependency only): `FakeAgentHarness`, `FakeGuard`, `FakeChannel`, `FakeProcess`, `InMemoryTaskRepository`, `TestEventBus`, `FakeTurnManager`. Never redeclare locally.
- Server-owned types (can't live in the `dartclaw_testing` barrel) have package-local shared support files — reuse, don't redeclare:
  - `test/api/workflow_test_support.dart` — one configurable `FakeWorkflowService` (extends `WorkflowService.lifecycleOnly`) for the workflow/webhook/chat-command route suites. Toggle `validateRequiredVars` for the chat-command path and `recordListCalls` when a test asserts `list:*` entries in `calls`; otherwise `list` returns the recorded `activeRuns`.
  - `test/turn_runner_test_support.dart` — `RecordingSseBroadcast` (capture-only `SseBroadcast`) for the TurnRunner governance suites, plus `FakeTurnRunner` (minimal real-`TurnRunner` subclass; `providerId` defaults to `claude`) and its no-op collaborators `MinimalHarness` / `NoOpMessages` / `NoOpSessions`, shared by `runner_routes_test` and `runner_observer_test`.
  - `test/whatsapp_test_support.dart` — one configurable `FakeGowaManager` (extends the `dartclaw_whatsapp`-owned `GowaManager`; not barrel-eligible). No-op lifecycle; records `sentTexts`/`sentMedia`, chat presence, and outbound order with `firstSent`; pass `running`/`status`/`pairedJid` to reproduce each route suite's permutation. Shared by the roundtrip/web/webhook/config-api suites.
  - `test/signal_test_support.dart` — one configurable `FakeSignalCliManager` (extends the `dartclaw_signal`-owned `SignalCliManager`; not barrel-eligible). Mutable `fakeHealthy`/`fakeRegistrationState`/`fakeLinkUri` drive status/registration; `*Throws` flags and `smsRequested`/`voiceRequested`/`lastVerifyCode` cover the pairing flow. Shared by the signal-pairing/web/config-api suites.
  - `test/delivery_test_support.dart` — `RecordingDeliveryService` (capture-only `DeliveryService` recording `deliver` calls), shared by `knowledge_delivery_path_test` and `schedule_service_test`.
  - `test/alerts/alert_test_support.dart` — `FakeAlertDeliveryAdapter` (capture-only `AlertDeliveryAdapter` recording `delivered`), shared by `alert_router_test` and `agent_execution_boundary_replay_test`. (The `CloudEventAdapter` fake in `google_chat_space_events_wiring_test` is a different type — kept local.)
  - `test/auth/auth_test_support.dart` — `authRequest({socketAddress, headers, path})` GET-request builder + `FakeConnectionInfo` (fakes `HttpConnectionInfo`; ports 443/3000), shared by `auth_middleware_test` (default path `/api/sessions`) and `auth_utils_test` (`path: '/test'`). Preserves every remote-address permutation.
  - `test/session_turn_manager_test_support.dart` — the real-`TurnManager`-subclass family (import the barrel with `hide FakeTurnManager, TurnManager` to avoid the callback-style barrel fake): `FakeTurnManager` (reserve/lifecycle + `reserveCalled`) and the archive-ordering trio `ArchiveCallTracker` / `RecordingSessionService`. Shared by `session_routes_test` (whose local `RecordingTurnManager` still extends the shared `FakeTurnManager`) and `session_chat_command_intercept_test`. Distinct from the barrel's callback-style `FakeTurnManager`.
  - `test/task/task_review_test_support.dart` — the review trio `RecordingMergeExecutor` / `RecordingWorktreeManager` (cleanup-recording) / `RecordingTaskFileGuard` plus `FakeRemotePushService` / `FakePrCreator`, shared by `task_review_service_test`, the channel-review integration test, and `task_routes_test`. (Distinct from the create-recording `CapturingWorktreeManager` in `task_executor_test_support.dart`.)
- `TaskExecutor` tests share `test/task/task_executor_test_support.dart` (imported by `task_executor_test`, `task_executor_workflow_oneshot_test`, `task_executor_worktree_test`, `retry_enforcement_test`, `budget_enforcement_test`). It provides the `TaskExecutorTestHarness` topology plus `buildWorkflowExecutor({...})` (collapses inline `TaskExecutor`/`TaskExecutorServices` ctors — pass only the collaborators a test exercises), `echoCliRunner(payloadFor, {onArgs})` / `successCliRunner()` (replace bespoke `WorkflowCliRunner` `/bin/sh printf` process-starters; `payloadFor` may branch on args), `readyProject()/cloningProject()/erroredProject()` + `fakeProjectServiceFor(project)`, and `initGitRepo({branch, extraFiles, integrationBranch})` for real-git fixtures. Prefer these over re-inlining.
- The three `task_executor_*_test.dart` suites are split by theme (core lifecycle/capacity/scope, `_workflow_oneshot_` one-shot CLI orchestration + token/session_cost mirroring, `_worktree_` project/worktree/git resolution) and share `WorkflowTaskExecutorTestContext` from the support file – a workflow-DB-backed topology wrapper (swaps in a SQLite-backed `TaskService`, owns `kvService` + workflow repos) exposing `setUp`/`tearDown`/`buildExecutor`/`seedWorkflowExecution`. The support file also publishes the shared fakes `FakeTaskWorker`, `CapturingWorktreeManager`/`BlockingWorktreeManager`/`StaticPathWorktreeManager`, and `CapturingTurnManager`/`BusyOnceTurnManager`. `FakeTaskWorker` is the one configurable `AgentHarness` stub for executor/budget/loop-detection tests – set `inputTokens`/`outputTokens` for budget assertions and `toolToEmit` to emit a single `ToolUseEvent` before the response delta (loop-detection sequencing); don't re-roll per-test `implements AgentHarness` stubs. The `session_cost` arithmetic that flows through `computeEffectiveTokens` (the public `dartclaw_core` billing-weight fn) is additionally unit-pinned in `workflow_one_shot_runner_helpers_test.dart`; the executor integration suites prove the end-to-end mirroring.
- Don't real-time-wait: use `pumpEventQueue()` for microtask drainage; reach for `waitForTaskStatus(tasks, id)` only when a real `/bin/sh` subprocess (workflow one-shot/CLI) must finish before the assertion.
- In-memory SQLite (`sqlite3.openInMemory()`) for storage-backed tests; temp dirs for filesystem.
- Suites run in parallel; keep them that way. `dart test` runs suites as isolates in **one OS process**, so ports, the filesystem, and the working directory are shared. Bind port `0`, keep fixtures in per-test temp dirs, and never assign `Directory.current` — inject it (`WorktreeManager(currentDirectory:)`). Breaking this forces the package back to `-j 1` (≈5× wall time). See `dev/guidelines/TESTING-STRATEGY.md` Layer 2 note.
- Template-rendering correctness (HTML structure, escaping) is asserted at Layer 2/3 against rendered output strings — visual layout is covered by manual UI smoke tests, not Dart tests.

## Key files
- `lib/src/server.dart` + `server_builder.dart` — composition root, route mounting.
- `lib/src/web/page_registry.dart` + `lib/src/web/pages/` — dashboard page registration.
- `lib/src/templates/loader.dart` (`expectedTemplates`) + `lib/src/templates/*.{html,dart}` — Trellis templates.
- `lib/src/static/controllers/` — Stimulus bootstrap + controller contract (`index.js`, `CONVENTIONS.md`, `dc_*_controller.js`).
- `lib/src/api/*_routes.dart` + `api_helpers.dart` + `sse_broadcast.dart` — HTTP/SSE surface. `session_routes.dart` is the session CRUD factory + composition root; cohesive groups live in sibling `session_{message,attachment,lifecycle,turn_status}_routes.dart` (each exposes a `register*Routes(Router, {...})` called from the factory), with the shared mutation coordinator and request helpers in `session_routes_support.dart`.
- `lib/src/turn_manager.dart` + `turn_runner.dart` (with cancellation and memory parts) + `turn_wait_status.dart` + `turn_governance_enforcer.dart` + `execution_coordinator.dart` (lifecycle/observability/model parts) + `worker_capacity_gate.dart` — turn lifecycle, status, allocation, reuse, and early cancel.
- `lib/src/task/task_executor.dart` + `task_service.dart` + `worktree_manager.dart` + `merge_executor.dart` — task runtime + git ops.
- `lib/src/container/container_manager.dart` + `security_profile.dart` + `bridge_binary.dart` + `gateway/` — container orchestration and host mediation.
- `lib/src/static/VENDORS.md` — vendored asset versions and upgrade commands; update when bumping any of the seven entries. `lib/src/static/fonts/` holds the JetBrains Mono woff2 subsets (variable weight axis, one file per unicode-range).
